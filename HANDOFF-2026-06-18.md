**How the engine works (`lib/diagnostics.ts`):**
- `buildSignals(seed, {outcome?, durationSec?})` → `CallSignals` — deterministic (FNV-1a `seeded()`,
  same style as the call sheet) so a given call always renders the same diagnosis.
- 9 pure `RULES` → `Issue[]`: barge-in not honored · tool-call timeout · escalation didn't connect ·
  off-script · low ASR confidence · LLM latency spike · network quality dropped · dead air ·
  **config drift** (`configVersionAtRun < agent.version`).
- Each `Issue` = `{id, ruleId, title, severity, turn?, timestamp?, rootCause, suggestedFix, fixTarget}`.
  `fixTarget = {level:"agent"|"deployment", id, section}`.
- `diagnoseCall(signals, {agent, deployment})` · `healthOf(issues)` → `{status, criticals, warnings}` ·
  `aggregateIssues(deploymentId)` (ranked severity×frequency) · `allOpenIssues()` ·
  `deploymentHealth(id)` · **`fixHref(fixTarget)`** (deep-link builder).
- **`fixHref` uses `deploymentHref()`** → `/deploy/inbound/[id]#section` or `/agents/[id]/edit#section`.
  **Never `/campaigns/[id]`** — that route does not exist (pre-existing dead link still on `/calls`
  line ~257; a cleanup candidate).

**Verified:** Diagnosis tab default with count badge + health header + issue cards + working "Fix this"
deep-links (resolve to real routes); Observe queue ranked with health roll-up + filters; renders
light **and** dark (the `--warning` token); diagnostic events fire; no console errors.

## 4. Diagnostics — Slice 2 (THE NEXT WORK, deferred, fully specced)

This thickens the spine **up** the hierarchy (deployment + agent) and adds the **capability check**.
The Slice-1 engine already emits `fixTarget.section` anchors (`#stack`, `#turn-taking`, `#prompt`,
`#channel`) — Slice 2 makes those anchors land and adds the config they reference.

**4a. Data model (`studio-x/lib/campaign-data.ts`)** — add the greenfield runtime config:
```ts
export interface TurnTaking { bargeIn: boolean; interruptible: boolean; endpointingMs: number }
export interface RuntimeTuning { region: "us-east"|"us-west"|"eu-west"|"ap-south"
  llmTimeoutMs: number; toolTimeoutMs: number; temperature: number; streamingStt: boolean }
// AgentStack gains:  tts.interruptible?: boolean ; turnTaking?: TurnTaking ; tuning?: RuntimeTuning
// Deployment gains:  configVersion?: number ; region?: RuntimeTuning["region"]
```
Seed **intentional contradictions** so the demo lights up: `agt_support_v2` → `tts.interruptible:false`
+ `turnTaking.bargeIn:true` (capability FAIL); `dp_ib_03` (UK, +44) → `region:"us-east"` (region-mismatch
WARN); set `dp_ib_01.configVersion = 42` vs agent `version:45` (drift). Extend `STACK_PRESETS`/`stackFor()`
to write sensible `turnTaking`/`tuning` defaults.

**4b. Engine (`studio-x/lib/diagnostics.ts`)** — add:
```ts
export type ConfigSource = "console"|"agent"|"deployment"|"sdk"|"provider"|"default"
export interface ConfigValue<T> { value: T; source: ConfigSource }
export interface EffectiveRuntimeConfig { /* llmModel, asrModel, ttsVoice, interruptible, bargeIn,
  endpointingMs, region, streamingStt, llmTimeoutMs, temperature, version — each a ConfigValue */ }
```
