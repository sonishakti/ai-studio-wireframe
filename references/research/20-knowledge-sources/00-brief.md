## What the product has today

Two knowledge surfaces exist, in two repos, and they do not agree. The real Console has a live API and a real vector-store type. The prototype has a mock API and a real connect-flow. Neither has a crawler.

## Agora fact-check

Sources: `agora-agents@2.4.0` (`ng-console/node_modules/agora-agents/package.json:3`), its type files under `dist/cjs/api/types/` (178 files), and docs.agora.io fetched 2026-09-17.

1. **The Conversational AI Engine contract carries no knowledge primitive.** Grep for `knowledge|vector|retriev|crawl` across every file in `node_modules/agora-agents/dist/cjs/api/types/` returns nothing. `Llm.d.ts` fields in full: `url · api_key · access_key · secret_key · region · model · system_messages · params · max_history · input_modalities · output_modalities · greeting_message · greeting_audio_url · failure_message · vendor · style · ignore_empty · greeting_configs · template_variables · mcp_servers · headers`. There is a typed `mcp_servers` and no RAG sibling. `LlmParams.d.ts` is `model · max_tokens` plus open properties. The public REST contract agrees: https://docs.agora.io/en/conversational-ai/rest-api/agent/join lists `llm.credential_mode · vendor · style · url · system_messages · greeting_message · failure_message · max_history · params` and never mentions `rag_config`, `search_config`, `kb_id`, knowledge base, RAG, retrieval or vector. **Requires Engine.**
2. **`llm.rag_config.search_config.kb_id` is real in our code and undocumented everywhere else.** It is what the Console writes when a base is attached (`ng-console/src/lib/agents/orchestration-properties.ts:441-445,696-710`). The SDK accepts it only because `Llm` ends with `[key: string]: any` (`Llm.d.ts`). It is a single id, and it is also the field the custom-config override check keys on (`orchestration-properties.ts:333-339`). Everything in this feature rides on a field with no published contract. **Requires Engine** to type it and to say whether a list is possible.
3. **Agora's own docs describe RAG as the customer's job, not the Engine's.** https://docs.agora.io/en/conversational-ai/develop/custom-llm: the customer stands up a `/rag/chat/completions` endpoint, implements the retrieval, injects the context into the message list, and points `llm.url` at it. "The Engine doesn't manage RAG internally." Studio's knowledge bases are therefore a Studio feature layered on top, not an Engine capability.
4. **Studio knowledge bases are a Console-backend resource.** Endpoints: `/api/v1/studio/knowledge-bases` for list, create, get, update, delete and documents (`ng-console/src/server/console-backend/studio-knowledge-bases.ts:201,208,224,310,325,339`), and `/api/v1/studio/agent_pipeline/{id}/knowledge-bases` for attach, list and detach (:190-192,235-237,277-279). The raw upstream payload keys are `created_at · created_by · description · failed_documents · name · processing_documents · provider · status · total_documents · total_size · updated_at · updated_by · uuid` (:121-135); documents are `created_at · file_size · file_type · name · status · updated_at · uuid` (:137-145). **There is no url, no source, no crawl, no schedule and no last-synced key in either shape.** A crawled site has nowhere to live in the current record. **Requires Engine** (the Studio backend half).
5. **The documented ingestion limits match the code.** https://docs.agora.io/en/ai/studio/build/integrations and https://docs.agora.io/en/conversational-ai/studio/build/integrations both say: "Supported file formats: PDF, DOCX. Maximum file size: 20 MB per file." Neither states a file count; the Console enforces 10 (`knowledge-base-document-lifecycle.ts:5`). Neither page mentions a URL source, website crawl, refresh, sync, re-index, retrieval tuning, OceanBase or Couchbase. The agent-side page https://docs.agora.io/en/conversational-ai/studio/build/customize-agent says only "A knowledge base provides your agent with additional context from reference documents. Select **+ Add Knowledge Base** to select or create a knowledge base." and does not say whether more than one can be attached.
6. **Nothing in either release-notes tree mentions this feature.** https://docs.agora.io/en/conversational-ai/overview/release-notes and https://docs.agora.io/en/ai/release-notes carry exactly one retrieval reference, v1.1 (March 27, 2025), and it is about what a *custom* LLM can do: "advanced capabilities such as Retrieval-Augmented Generation (RAG), multi-modal processing, and tool invocation." No entry mentions knowledge bases, crawling, OceanBase, Couchbase or vector stores. So OceanBase ships in the Console behind a flag with no public documentation, and Couchbase exists only as a test-fixture string.
7. **The pricing fact constrains the schedule control.** Conversational AI Engine is a flat $0.10 per agent-minute, charged the same on a BYO key; audio RTC bills separately at about $0.00099 per participant-minute. Crawling, re-crawling and index size move none of it. A refresh schedule must never be presented as a cost control. The real per-turn cost is latency, and the prototype already says it out loud: "retrieval adds this to every turn's latency" (`external-retrieval-form.tsx:313`).

## Already decided

- **Reuse, don't redesign** (owner, 2026-09-12): things that belong together live together and look the same, "one door per action", "no control for what Agora does by default". A crawl source extends the knowledge row; it is not a fifth connect-an-external-thing surface.
- **Wave 1 already ruled on Couchbase branding.** "The roadmap item says 'integrate Couchbase as a RAG provider'. Both the connector research and the focus group independently argued against building that literally: no persona asked for Couchbase by name (they asked not to re-upload 40k docs into a black box), a fourth vendor-named connect-an-external-thing door would deepen the existing Knowledge/MCP/Connectors IA tension, and Couchbase was one of five systems users named." (`references/wave1-implementation-log-2026-07-29.html:205`). Locked in code at `studio_x_2/lib/agent-resources.ts:37-44`.
- **Connected is not working.** "a wrong embedding-field name produces a perfectly healthy connection that retrieves nothing" (`wave1-implementation-log-2026-07-29.html:223`). Two tests shipped because of it. A crawl inherits the rule: a green "Crawled" chip is not proof the agent can answer.
- **Every distinguishable failure gets its own message** with its own fix, never one "Connection failed" (`wave1-implementation-log-2026-07-29.html:231`).
- **Advanced things must not make a beginner feel behind.** "a first-time builder who doesn't know what a vector store is should never feel behind for skipping it" (`wave1-implementation-log-2026-07-29.html:212`).
- **Honesty floor** (LEARNINGS §20, 2026-07-29 v7): simulated-preview disclosures, Live/pending truth, deploy blockers and override locks are "never trimmed away". "Not supported" is a state, not an edge case.
- **Copy discipline** (CLAUDE.md working rules): "never ADD UI text without asking", one short line under a control at most, background knowledge behind InfoHint, verb titles in sentence case, no arrows, no em dashes.
- **Control strokes** (CLAUDE.md, P0 2026-08-10): every input, select, textarea, checkbox and switch boundary uses `--stroke`, checked in both themes.
- **Builder section names are locked** (LEARNINGS, 2026-07-30): "Voice & Models · Deployment · Prompt & knowledge · Test · Go Live". Knowledge lives inside *Prompt & knowledge* in the prototype; in the real Console it lives in the agent's **Actions** tab (`agent-detail-page.tsx:727`, `?tab=knowledge` folded at :868). Two homes, one feature.
- **The Integrations IA tension is open, not settled** (CLAUDE.md, Open IA tensions #3): "Integrations (agent-scoped: KB · MCP · CRM connectors) vs Extensions Marketplace (project-scoped) — labels don't make the distinction clear." Do not resolve it inside this feature.
- **Pricing** (standing): $0.10 per agent-minute flat, identical on a BYO key. No control here may be premised on model or index choice moving the Agora bill.
- **Where to build** (design-ops protocol, step 5, 2026-09-08): the surface exists in the live Console, so the prototype goes on `ng-console` `design/sandbox`, additive only, with the pattern `src/lib/agents/<feature>.ts` + test, `src/components/console/<feature>-row.tsx` + test, a mount of eight lines or fewer, and one i18n block. ## Open questions for the owner

1. **Which base does the agent actually query when several are attached?** The attach API takes `knowledgeBaseIds: string[]` (`studio-agent-attachments-api.ts:24`); the Engine payload carries one `kb_id` (`orchestration-properties.ts:696-710`). Every crawl task lands on top of this answer.
   - *One primary, the rest are inert:* keep today's behaviour, label the primary in the list, and say on screen that only it is queried. Cheap, honest, admits the limit.
   - *Many, with `kb_ids[]` from the Engine:* the row becomes an ordered list and eligibility rules apply. Requires Engine.
   - *Many in the Console, merged server-side into one index:* the UI stops promising order at all, and "which base answered" becomes a retrieval-result question, not a config one.
2. **Couchbase: a new `kbType` value, or the prototype's generic provider form ported into the Console?** The Console's shipped precedent is `kbType: "oceanbase"` with a hard one-at-a-time rule; the prototype's shipped precedent is a provider-agnostic connect form.
   - *`kbType: "couchbase"`:* one door, one enum, the OceanBase mixing rule extends to it, nothing new in the IA. Needs one value added by the Studio backend.
   - *Port the generic form:* keeps Wave 1's reasoning and gets Pinecone and custom endpoints for free, but adds a second external-store surface to a repo that has one, against the reuse rule.
   - *Neither:* Couchbase stays a Studio-only concierge POC (`clickup-q3-roadmap-export-2026-09-03.tsv:189-190`) and never reaches the Console.
3. **Is a crawled site a source inside a knowledge base, or a kind of knowledge base?** This decides whether refresh is a base-level control or a per-source one, and whether a base can mix uploaded PDFs with a crawled site.
   - *A source inside a base:* the base gains a sources list (files today, a site tomorrow), one door, no new list surface, and the existing upload row extends. Freshness becomes per source.
   - *Its own kind, like OceanBase:* simplest to ship and easiest to explain, but splits the model and means a customer who has both uploads and a site keeps two bases.
4. **Authenticated crawl: whose credential, and is this even a crawler task?** 868kyjfnu may belong to feature 19 · Tools & connectors (https://app.clickup.com/t/868m0mf40) rather than here.
   - *A secret on the crawl source:* the user pastes a cookie or header, stored write-only and read back as "configured", exactly as `external-retrieval-form.tsx:188-199` already does.
   - *OAuth per system* (Confluence, Notion, Zendesk): then this is the connector marketplace's job, not a crawler's, and the task moves.
   - *Public pages only,* and the product says so plainly.
5. **What does a schedule promise while no field can enforce it?** There is no interval anywhere in the contract (fact-check 4).
   - *Ship it inert, marked "Requires Engine",* the way 07 shipped the Backup providers row with a disabled test and the caption as its `title`.
   - *Ship "Refresh now" only:* one button, honest, useful the day it lands, and the schedule arrives when there is a field to hold it.
   - *Draw nothing* until the Studio backend adds the source record.
6. **Retrieval tuning: per base, per agent, or not at all?** Today the four controls exist on screen and save nothing (`external-retrieval-form.tsx:338-380`), which is the worst of the three.
   - *Per base:* text field, embedding field, top-k and threshold move onto the base and persist. Only meaningful for an external index, where the customer owns the schema.
   - *Per agent:* top-k and threshold are how *this* agent reads a shared base, and they belong next to the knowledge row in the builder.
   - *Not at all:* Agora picks, which is what "no control for what Agora does by default" would say. Then the Advanced block gets deleted rather than wired.
