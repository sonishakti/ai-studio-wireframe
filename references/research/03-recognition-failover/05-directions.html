Why this shape

  • A is the control — the only direction with a field to write. Vocabulary is a property of the transcriber, so it sits under Language in the ASR drawer, where the vendor and model that decide the mapping already are.
  • D is the recap and the failover. The Models-tab ASR row shows language · count · backup; 07's ASR backup gains one eligibility flag (868kyv45t's "keyword or dictionary support"). No second fallback row, ever.
  • C is one line. Talk already streams You: transcripts; the verdict compares them to the list. Meets the "test representative phrases" criterion without a new CTA.
  • Never fake a capability. Vendors without a field show the list dead and named; Deepgram below nova-3 the same; OpenAI says it is a prompt. Denoising and ASR-side pronunciation get no control (E rejected) — the brief records the gap for the owner.
  • B waits for a yes. Inert "Also understands" chips are cheap and honest, but they promise an Engine behaviour with no date; the owner decides. Widening the primary list from 10 to the contract's 32 tags is the real first step.

What writes to real properties

  • asr.keywords: string[] — ares. Written as an array (owner Q1 confirms shape before the slice leaves the sandbox).
  • asr.params.keyterm: string — deepgram, only when model is nova-3; terms joined by a constant DEEPGRAM_KEYTERM_SEPARATOR (owner Q2).
  • asr.params.phrase_list: string[] — microsoft.
  • asr.params.input_audio_transcription.prompt — openai; appended behind a marker so the user's own prompt is never overwritten. Off (draft only) until owner Q6 says yes.

What stays in sessionStorage

  • The word list for a vendor without a field (so switching vendor and back restores it) — key ng-console.design.03.vocabulary:<agentId>.
  • B's "Also understands" chips, if built. Never written to properties; 868kykbfg has no field.

What stays disabled with a Requires Engine caption

  • B's whole row (Requires Engine language switching), if built.
  • 07's Test failover button — unchanged (Requires Engine failover · Nov).
  • Not built at all: denoising, ASR-side pronunciation (E). Recorded in 00-brief.md as contract gaps.

How 07's row is reused for the ASR backup

  • No new row. planProviderFallback already ranks ASR candidates by language; it gains a vocabulary flag from resolveAsrVocabularyField(candidate.vendor). A backup that cannot carry the words stays selectable but shows no vocabulary in the Eligible column and in the picker — dead-not-hidden, same idiom as the language chip.
  • The Models-tab recap line names the backup (backup Deepgram) from the same plan, so the ASR row and 07's row never disagree.
  • When the Engine contract lands (868kyqzfy · Nov), the flag feeds pre-publish validation — "Incompatible … combinations are rejected before publication" (868kyv45t).
