What we take from each

  • C is the spine. A criterion is an assertion with a name. EvalAssertion gains name and criterionId, a Scorecard is a named list of them, and the agent points at one. The sentence in the builder and the sentence on the calls list are one record, so they cannot drift.
  • A's deletion survives whole. The phone-number Success Evaluation and its useState pair go, and the transcription gate the data points already have is extended over the criteria. That part of A was right, and it is free.
  • B's per-criterion reporting is the call side. Met · Not met · Unknown, each with the judge's one line, plus Not scoreable with its reason. The call sheet reuses the assertion-row grammar ResultSheet :501-509 already draws.
  • E gives us its one door. Save-as-test mounts on a criterion that was not met, so a real failure becomes a decision check carrying that same criterion. The sheet, the prefill path, the transcript block and the event are all built and dead today.
  • D folds away until a second agent needs the same sentence. The Scorecard type carries an id and a name from day one, so the library is a list page over it later, never a migration.

What we are not doing, and why

  • No Score column. Call Outcome already answers this question for every user, and putting a second column beside it would mean two columns and two answers. Its source is replaced: the badge is computed from the criteria, and the word Cannot Predict, which names neither a judgment nor a reason, becomes Unknown with a printed one.
  • No second table. Runs are stored, and the run record is read by the rows that already exist: the status cell, the pre-flight Tests row, the call sheet. Nobody gets a Runs table.
  • No recording review. 868ka24am needs a recording the Agora contract does not name, and four Engine rows are in flight for it. The audio row keeps its stated reason and the criteria block says Requires Engine where the playback would go.
  • No self-improving write. One vendor ships this and it never writes on its own (learning 5). A failing criterion names the setting to fix and links the control that exists for that channel, the way test-section.tsx :70-93 already does. The accept-or-reject panel on the Composer is 868kbyqf6 and it needs the run record this build creates, so it goes after, not with.
  • No repeat-count control. A text run starts no agent, so it repeats 3 times and the row carries the rate. An audio run costs $0.10 a minute and runs once, with the price on the button. Nothing to configure, and no way to quietly multiply a bill.

Audit corrections

Three hostile audits read the build plan against the locks, the honesty floor and the compiler. They refuted it. What follows is what they killed, what survived them, and the two places the directions were kept over an auditor's objection. The spine is unchanged: a criterion is an assertion with a name, one record. What changed is that only one of the two sides can carry a number today.

Killed on the honesty floor

  • Every production score. scoreCall(callId, scorecard) was handed a string and asked for per-criterion verdicts and a judge's sentence. The words it would judge do not exist: the transcript store is roadmap line 152. The call sheet would have printed a reason line above four canned lines of ACME Corp copy that contain no refund, no ticket and no callback. Cut. The Call Outcome cell now prints one honest state, Not scored, with the dependency named once under the table.
  • Met 96/100. generate() makes 28 rows across 10 telephony deployments, and the design has no window, no cohort and no sample-size control. 100 was not computable from anything on screen. Cut with the production score.
  • Not scoreable. A retention claim about a named customer call, derived from a hash. opt_out is set at join and is not readable back per call, and grep -rn opt_out over lib components app returns nothing. This was the worst line in the plan. Cut, with the state, the badge and its reason string.
  • ~$2.40. runEstimate returns (seconds / 60) × 0.10; three conversation cases at 74s is 222 seconds, which is $0.37. The button prints what the derivation returns and the copy now says the same number. A 6× error on the one control that quotes the pricing lock.
  • Unknown, errored and the second verdict vocabulary. CriterionVerdict was a third word list beside AssertionVerdict, and neither new word had a producer. This repo already condemns that shape twice, at campaign-data.ts :154 and :163. One vocabulary, "pass" | "fail", and a criterion the last run never judged renders as an absence, Not run, which needs no enum value.
  • scorecard_reviewed. The P0 event fires when two scored sides are on screen together. One side cannot exist yet, so declaring the event would be declaring a lie. criterion_authored ships, because it fires.

Killed on the locks

  • The second criteria editor. ScorecardBlock was mounted in StepAnalysis and in the Test section. StepAnalysis itself has two mounts, so the Add criterion button would have landed on four surfaces. The brief sets the ceiling in one line: "There are already two Success Evaluation controls and two stores. 14 removes one, it does not add a third." One editor, where the grading sentence already lives. The Test section and the docked panel mount ScorecardSummary, read only, with one door: Open scorecard.
  • scorecardId on AnalysisConfig. That type is persisted twice, in the wizard draft and at sx:call_capture:agt_default, so the criteria would have been shared and the pointer to them would not. It also had no writer and a truthy default, which would have printed the scorecard as pre-flight evidence on 100% of agents: defect 11 made unconditional. Cut. The criteria are the attach state: a scorecard with no criteria is not reported as an output.

Killed by the compiler

  • No mount site had an agentId, and every store key was built from one. TestsSection, TestSection and StepAnalysis have no such prop, and <ScorecardBlock agentId /> passes true. The id is now threaded the way test-panel.tsx :223 already threads it, draft.agentId ?? "draft", with the Monitor sheet passing "agt_default" to match the key it already owns.
  • The prefill was not the type the call sheet holds. CallTranscriptTurn is {speaker, text} and EvalTurn is {role, text}. An adapter ships in lib/scorecard.ts, typed structurally so a lib never imports a component. The persona fields a real call cannot know are left empty for the author to write, which the sheet's own canSave already requires.
  • Two deleted fields had unnamed consumers. an.successEval at deploy-preflight.tsx :192 and the Call Outcome filter at calls/page.tsx :299, which would have gone on offering "Cannot Predict" beside a column that no longer says it. Both are in the plan now.
  • Module-scope storage reads. const CALLS = generate() runs at module scope in a client file. Under the corrected plan the calls list reads no store at all, so the hydration split cannot happen.

Kept against an audit, with the reason

  • The stored run, the repeat count and the rate. An auditor called the run side synthesized too. It is, and legitimately: Studio owns a test transcript at the moment it makes one, and learning 3 is explicit that a rate, not a pass, is the evidence. What is corrected is the format. A rate prints only where there is a rate: text runs repeat 3 times and the row reads Pass 3/3 · text, and a single audio run keeps today's cell, Pass · audio 1:12, rather than 1/1. Giving audio three repeats would treble a bill the KPI's own counter-metric watches, and the directions refused a repeat-count control for that reason.
  • No gate on the criteria editor. Both the directions and an audit wanted the block disabled when "Store call transcripts" is off, the way data points are. Refused, on a fact: criteria grade every test run, and a test run needs no stored call transcript. A gate there would be a false dependency. Defect 10 is closed instead by the block stating what grades what, and by the switch it was attached to ceasing to exist.

What this costs the JTBD

Half the headline sentence ships. The named checks give a number before publishing, on a run that is stored, repeated and comparable across a tab reload. They do not give a number on the calls the agent took, because nothing keeps those words. The compare row, the criterion-edit question and the P0 event all wait on the same Engine row, which is why the open question for the owner has changed: it is no longer how a re-scored criterion subtracts, it is what the Call Outcome column shows while it cannot be computed.
