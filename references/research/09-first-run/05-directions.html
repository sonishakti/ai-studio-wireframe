Verdict — converge A + C + E

Why this shape

  • A is the surface. Import is a third row in the create modal; the report is step 2 of the same sheet. Meets 868kyj9w3's "show which settings were mapped, changed, or could not be imported" before the create call — where the user already starts.
  • One mapper, three consumers. agent-import-mappers.ts produces the LANDS / CHANGED / DROPPED rows; the same row shape renders the import report (A), the migration diff (C) and, later, the Concierge proposal details (B). DROP_REASONS is enforced in one table, so nothing can be dropped silently anywhere.
  • C is one button on an alert that already exists. Today the user is told "Configuration needs updating" and left to edit JSON; the diff sheet turns the release notes into a confirmable rewrite and ends on "republish to take effect".
  • E is required anyway and costs no screens. The four stages are the benchmark 868kbyun1 needs; the Home caption is the only visible piece.
  • D and the gallery are owner calls, and the verdict doesn't depend on them. A works on an empty list or next to a pre-provisioned default; B follows once the mapper exists (a Studio MCP agents_import wrapping it).

Stays out

  • Template gallery / recipes (868kyr03v, locked). Bland · ElevenLabs sources. Batch import UI (P2 gets the mapper via API/CLI later).
  • Any field the Engine has no contract for is dropped with "Requires Engine" — never emulated.
