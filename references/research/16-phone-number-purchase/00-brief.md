## What the product has today

Two codebases hold the answer and they disagree with each other. The **live Console** (`ng-console`) has a real, wired phone-number surface backed by a real API. The **prototype** (`studio_x_2`) has a richer-looking one built on mock data, and it says out loud, in seven places, that Agora does not sell numbers.

## Agora fact-check

Cited against `ng-console/node_modules/agora-agents@2.4.0` (`dist/cjs/api/...`) and `docs.agora.io/en/`, read 2026-09-17.

**The contract has a phone-number resource, and it is import-only.** `dist/cjs/Client.d.ts:3,21-22` exposes `phoneNumbers` and `telephony` clients. `api/resources/phoneNumbers/client/Client.d.ts` documents five methods against `v2/phone-numbers` (`Client.js:83,150`): `list` ("Retrieve a list of all imported phone numbers under the current account"), `add` ("Import a pre-configured phone number that can be used for inbound or outbound calls"), `get`, `delete`, `update`. Note the endpoint is **account-scoped, not project-scoped**: there is no `appid` in the path, unlike the call API.

**`provider` is a closed enum of two values.** `api/resources/phoneNumbers/client/requests/AddPhoneNumbersRequest.d.ts`: `const Provider = { readonly Byo: "byo"; readonly Twilio: "twilio" }`. The same enum repeats on `ListPhoneNumbersResponseItem.d.ts`, `GetPhoneNumbersResponse.d.ts` and `UpdatePhoneNumbersResponse.d.ts`. There is no `agora`, no `bandwidth`, no `resold`. **A number bought from Agora has no value to identify itself with today.** → **Requires Engine.**

**The full add payload** (`AddPhoneNumbersRequest.d.ts`): `provider` (required) · `phone_number` ("Telephone number in E.164 format") · `label` ("A label used to identify the number") · `inbound?` · `outbound?` · `inbound_config.allowed_addresses?: string[]` · `outbound_config.{ address?, transport?, prefix? }`. Seven fields. No country, price, number type, capability set, order id, provisioning status, owner, compliance record or verification state. Every one of those is **Requires Engine**.

**Update can change almost nothing.** `UpdatePhoneNumbersRequest.d.ts` accepts only `inbound_config.pipeline_id` and `outbound_config.pipeline_id`, each nullable to clear. Assigning a number to an agent is therefore already a two-field write, which is good news for assign and reassign, and means "reassign" needs no new primitive.

**Read returns the binding, not an inventory row.** `ListPhoneNumbersResponseItem.d.ts`: `provider · phone_number · label · inbound · outbound · associated_pipeline { pipeline_id, pipeline_name } | null · inbound_config | null · outbound_config | null`. 868kyjfny asks Studio to "Show purchase, billing, assignment, and provisioning status … and the current owner". Of those five, **only assignment is readable**. → **Requires Engine.**

**Delete is not a release.** The SDK's own comment on `delete` (`client/Client.d.ts`): "This operation only removes the number configuration from the Agora system; the number stored with the phone service provider is not deleted." The prototype's Release copy (`deploy/phone-numbers/page.tsx:200`, "returns it to the vendor pool") is already stronger than the contract supports, and for a resold number the truth flips again: releasing it would stop the rental. **Two different actions currently share one word.**

**Caller ID is a free-text E.164 field with no entitlement check.** `api/resources/telephony/client/requests/CallTelephonyRequest.d.ts` takes `sip: { to_number, from_number, rtc_uid, rtc_token }` against `v2/projects/{appid}/call` (`telephony/client/Client.js:107`). `from_number` is documented as "Caller ID (the number that initiated the call), in E.164 format" with nothing tying it to an owned or verified number. That is the hook 868kykk8y needs and the reason verification state cannot be enforced at call time today. → **Requires Engine.**

**Telephony errors have their own shape.** `api/types/TelephonyErrorResponse.d.ts`: `{ error_type?, description? }`, explicitly "not the Agent Management `detail`/`reason` shape". 868kyjfny asks for "actionable failures"; the only failure envelope that exists is a free-text description, so a purchase failure taxonomy (number taken, KYC pending, country unavailable, payment declined) is **Requires Engine**.

**There is no CPS, concurrency or capacity field in the SDK at all.** `grep -rn -i "phone|pstn|telephon"` across `dist/cjs/**/*.d.ts` returns only the two clients above and one unrelated audio-latency comment. 868keb6t2 has no API surface. → **Requires Engine.**

**Docs.** The public tree documents the intent in Studio's own words: "Import phone numbers from your SIP trunk provider and assign them to agents for inbound calls, or use them as caller IDs for outbound campaigns." (https://docs.agora.io/en/conversational-ai/studio/overview). The SIP setup page names one provider, Twilio Elastic SIP Trunking, tells you to "Use your Termination URI as the SIP Trunk Address", and says username and password may be left blank (https://docs.agora.io/en/conversational-ai/studio/deploy/sip-trunk). The release notes date the whole capability: v2.0, November 15 2025, "A set of phone number management APIs is also added for handling numbers **connected to** Conversational AI Engine", and, load-bearing for pricing, "The telephony feature is currently in Beta and is provided free of charge." (https://docs.agora.io/en/conversational-ai/overview/release-notes). **No page on docs.agora.io documents the phone-number management endpoints themselves**; `/conversational-ai/rest-api/phone-numbers/add`, `/conversational-ai/rest-api/phone-number/import`, `/conversational-ai/telephony/overview`, `/conversational-ai/rest-api/telephony/start` and `/conversational-ai/rest-api/overview` all return 404. The installed SDK is the only specification.

**Pricing, confirmed.** https://docs.agora.io/en/conversational-ai/overview/pricing: $0.10 per minute for the Conversational AI Engine audio task, "First 300 minutes are free", and "You are charged the same price even if you bring your own key (BYOK)." **The page documents no telephony, SIP or phone-number charge.** Combined with the Beta free-of-charge note, today the SIP leg bills $0 and the agent bills $0.10 a minute. A resold number introduces the platform's **first recurring per-resource fee and its first per-minute telco fee**, neither of which any existing meter, plan card or spend cap models. `PLAN_USAGE` (`campaign-data.ts:1184-1196`) has a minutes axis and a dollar cap; it has no line-item axis. The `ConcurrencyCard` separation of "included vs purchased" (`concurrency-card.tsx:34`) is the only precedent for a subscription line living next to per-minute usage.

- **A3's durable rules** (LEARNINGS.md:518) carry over intact and should not be re-derived: "the flow ENDS on a user-placed test call, never a 'saved' checkmark, provisioning success ≠ call success"; "stored credential masked + Disconnect ≠ carrier revocation"; and it "folds into the EXISTING add-phone-number-sheet as a Quick | Manual toggle so all entry points inherit it". - **Copy discipline** (CLAUDE.md): never add UI text without asking; one short line under a control; no prose in a disabled input. Note that removing the seven "Agora doesn't sell numbers" strings is a **deletion**, which needs no permission, but every replacement string does.
- **Honesty floor** and 868kykk8y's own clause agree: "Do not promise that every carrier will display a brand or that verification guarantees pickup."
- **The standing research risk** (`references/design-backlog-q3-roadmap-2026-09-03.html`): "R2 journey has steps design cannot invent. Pair with the Bandwidth PoC owner in week one; design the known steps, placeholder the rest."
- **Two PRD questions were already raised on 2026-07-29 and never answered.** They are questions 2 and 3 below, verbatim from the PRD's open-questions list.
- **I never buy, upgrade or change billing to reach a state** (`references/design-ops-protocol.md`, rainy-day rule). The purchase flow gets captured up to the point money would move and stops.

## Open questions for the owner

Six questions. Each one changes a screen. Everything else in this feature can be designed without them.

**1. What does the first-run home become once numbers are purchasable?** This is the ⚠ lock.

- **(a) Nothing changes. The card still lands on usage.** The ceremony keeps "no number to buy", Aria stays live in the browser, and the 150-minute nudge (`free-minutes-nudge.tsx:110-112`) stays the only card moment. Buying a number is a later, deliberate act from the numbers page. Cheapest, protects the A1 advantage, and keeps one card-capture surface. Cost: the number, which is what makes an agent real to a caller, stays behind a wall the first run never mentions.
- **(b) The card moves to the number.** First run offers "Get a number" as the second step, and the card is captured at purchase rather than at minute 150. Matches what four of five competitors do and makes the first paid moment concrete. Cost: it reintroduces a paywall into a first run that was deliberately built without one, and it breaks the half-tier nudge whose entire premise is a card before exhaustion, not a card before value.
- **(c) One free number, then card.** Agora grants a number on signup the way it grants Aria, and the card lands when a second number or the 150-minute mark arrives, whichever is first. Strongest activation story and the only option that keeps both A1 and the nudge intact. Cost: real recurring carrier spend on every signup including bots, and a hard cap on which countries a free number can come from.

Related and blocking on the same answer: **`billing/plans/page.tsx:48-49` already promises "1 phone number" on Free and "10 phone numbers" on Pro.** If the answer is (a) or (b), that copy is a bug and gets deleted. If (c), it becomes the spec.

**2. Does BYO SIP remain a parallel path, or become the fallback?** Raised in the PRD on 2026-07-29 and still open: "which countries, and does BYO SIP remain a parallel path? The purchase flow design needs the answer for its empty/unavailable states."

- **(a) Peer paths.** The add sheet grows a third mode, Buy | Quick connect | Manual SIP, and the empty state offers both. Honest for Entel and Concentrix, who already own trunks.
- **(b) Buy leads, BYO demoted.** Buy becomes the primary and BYO moves behind "I already have a number". Better for the 0-to-1 developer, worse for the named enterprise accounts.
- Either way the answer sets what an unsupported country shows: (a) can fall back to "connect your own"; (b) has to dead-end.

**3. Does reseller-mode usage bill through existing postpaid, or a new SKU?** Also verbatim from the PRD, 2026-07-29: "Determines what the credentials surface promises." The answer decides whether a number is a line item on the Agora invoice beside the $0.10 minutes, or its own subscription with its own cycle. It also decides whether the spend cap covers a number rental. Today the cap governs per-minute usage only (`concurrency-card.tsx:34` keeps line fees explicitly outside it), and a customer who hits their cap with a rented number must not lose the number.

**4. Which countries are in the first slice?** The tickets disagree: 868keb672 says "US/Canada, Peru and Brazil", 868kj8qyh says "US, Chile (TBD)", and the Design Tracker says US then beyond. If the first slice is US-only the first screen is a search box with area code and number type. If it is four countries across three regulatory regimes, the first screen is a country picker and every downstream state is per-country. These are different designs and I should not build the second speculatively.

**5. Where does KYC sit relative to money?** 868keb672 says most countries require it for outbound and that "Bandwidth provides APIs and an onboarding agent". Three placements, three products:

- **Before search.** The user proves who they are, then only sees numbers they can actually have. No dead ends, worst first impression.
- **Before purchase.** Search is open, KYC is the checkout step. Standard, and the one the concurrency sheet's shape already fits.
- **After purchase, number pending.** Money moves, the number arrives with a review state, and calls are blocked until it clears. Fastest to a receipt, and it needs a pending state on every surface that shows a number, which is six of them.

**6. Is verified and branded calling (868kykk8y) in scope for this design, or its own feature?** It is P1 and it is a different object: a business calling profile that numbers attach to, with per-country enrollment states and rejection reasons. Designing it now means a second resource model before the first one is settled. Deferring it means the number detail page gets a section later that changes its shape. If it is in, it needs its own JTBD and its own rainy scenarios, and the 24-day estimate is short.

**One question I am not asking**, because the contract answers it: whether Studio can identify an Agora-sold number today. It cannot. `provider` is `byo | twilio` and nothing else (`AddPhoneNumbersRequest.d.ts`). Every design below the purchase screen depends on a third enum value existing, and that is an Engine dependency to raise now, not a design choice.
