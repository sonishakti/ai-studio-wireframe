2The premise — the agent ships working; channel comes first

This is the PM direction, and it matches the 2026-06-17 activation realignment already in LEARNINGS §20: a default agent is auto-provisioned and live on signup. The developer never builds an agent from zero — they point a working one at a channel.

Universal by default

Voice, models, turn-taking, history — all preloaded with defaults that work everywhere. Nobody should touch them to go live. They exist in the tree for the developer who needs to change them, not as steps.

Channel is the fork

The first real decision. It determines the prompt’s shape (“Thank you for calling…” vs “Hey {{name}}, I’m calling from…”), which variables exist (batch CSV columns), which setup applies (number vs embed vs SDK), and which settings even render.

Prompt follows channel

The prompt is written for a channel, so it can’t come before one. Production already enforces this direction: batch deploys are blocked unless the prompt’s {{variables}} are covered by the CSV — the dependency runs channel → prompt, never the reverse.

Consequence for the IAv2 ordered sections by the layered convention (Conversation first). v3 orders them by the journey: Channel → Prompt → Go live is the critical path; Voice & speech, Models, and Knowledge & Tools become “only if you need to” — present, findable, never in the way. The convention mapping survives as each section’s layer tag, not as the nav order.

What changed from v2Channel moved from position 4 to position 1 — it’s the fork everything depends on. Brain split: Prompt (system prompt + greeting + persona — the words, rewritten per channel) is Set up; Models (architecture + model choice — the machinery) is Customize. Greeting moved from Conversation into Prompt — it’s channel-shaped copy, not a speech setting. Review & deploy and draft-state now live together in Go live, resolving v2’s T3. The “Optional” junk drawer stays dissolved; “Customize” is not a junk drawer — each section is a coherent layer, just ordered after the critical path because its defaults already work.

Weight checkSix doors, but the walk is three: Channel → Prompt → Go live. Channel’s subsections are mutually exclusive per agent (a phone agent never sees widget or batch rows), and the three Customize sections start collapsed. The first-run TOC a developer actually reads: 3 sections ≈ 11 rows.

6Deviations from the convention & rules applied

Per the brief: sections were merged, added, dropped, or reordered only where the convention didn’t survive contact with production — or with the journey.

  1. Journey order beats layer order. The convention’s stack (Conversation → Brain → … ) describes how an agent runs, not how a developer configures one. Nav order follows the journey (Channel → Prompt → Go live, customize in between); each section keeps its layer as a tag so the convention mapping is never lost.
  2. Channel first, because prompt is channel-shaped. The greeting and prompt are written for a channel (“Thank you for calling…” vs “Hey {{name}}, I’m calling from…”), and batch variables come from the channel’s CSV. Production already enforces this direction — deploy blocks when prompt {{variables}} aren’t covered by CSV columns.
  3. 100% production rule. The tree contains only what ships in studio_x_2 today. Gated, type-only, and roadmap items are parked in §5 with reserved homes.
  4. Brain splits into words and machinery. Prompt (system prompt, greeting, persona) is a required rewrite; Models (architecture, LLM choice) is a default nobody must touch. One convention layer, two journey positions.
  5. Nine layers → six sections. Orchestration and Safety & Governance dropped (zero live items). Memory + Tool Layer merge into Knowledge & Tools. Execution Runtime reduces to a BYOK cross-link row. Session becomes Go live and absorbs review/deploy + call capture.
  6. “Select agent type” retires; “Environment” rejected as its replacement. The section is Channel: “Environment” is the meta-bucket’s name in the convention and reads as infra (staging/env-vars) to developers, and the options mix medium with direction — they aren’t environments.
  7. Global utilities stay global. Name/ID, Custom config JSON, Import, and Talk operate on the whole agent — header, not sections.

7Open tensions — for the improve pass, not this draft

T1 · Channel-keyed prompt templates

Today the voice pick seeds the starter prompt/greeting. v3’s logic wants the channel pick to seed them (inbound vs outbound openers). Content exists; the seeding trigger moves. This is the one production behavior the reorder actually changes — flag it in the build slice.

T2 · Switching channel after writing the prompt

Production stashes channel config on a type switch, but the prompt isn’t channel-stashed — an inbound prompt silently survives a switch to batch. With channel-first this becomes the main destructive edge; needs a “re-seed or keep?” decision in design.

T3 · Persona placement

Persona (personality/tone) now sits in Prompt but is still edited inside the voice editor. Fine for IA, awkward for the edit surface — decide whether the editor deep-links or the fields move.

T4 · The speed/cost preset spans sections

Fastest/Balanced/Cheapest writes STT + LLM + TTS at once — it lives in Models but mutates Voice & speech fields. Needs a cross-section affordance in design.

T5 · Widget styling’s true layer

By the convention it’s “Streaming UI” → Conversation; kept with its channel so one artifact isn’t split across two pages. Revisit if styling becomes channel-independent.

T6 · Labels untested

“Knowledge & Tools”, “Go live”, and the Set up / Customize / Ship group names are unvalidated. Tree-test before locking — especially whether “Customize” reads as skippable (intended) or second-class (not).
