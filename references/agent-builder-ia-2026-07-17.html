2The convention we’re aligning to

The three buckets are the meta-grouping — they become the LHS group labels. The convention’s nine layers collapse to five sections for v1: layers with nothing live in production are dropped (parked in §4), and small adjacent layers merge. Nine doors is daunting; five is walkable.

Agent — the brain

Model, system instructions, persona, behavior — plus the conversation surface it talks through. For Agora: Conversation + Brain.

Environment — the hands

Files, APIs, MCP servers, credentials, network — where the agent reaches the world. For Agora: Knowledge & Tools + Channel.

Session — the execution

Connects agent + environment: state, streaming, progress, replay, debugging. For Agora: Session (test & talk, transcripts, data points, draft-vs-live state).

Navigation behavior (the ask)LHS is an outliner: each section row expands to show the table of contents of its page — every subsection is a link. Clicking a subsection navigates the RHS straight to it; the user never has to scroll the RHS to find anything. This matches the existing scroll-spy rail mechanics — the change is the grouping and the expandable TOC level, not the interaction model.

What this dissolvesThe “Optional” group disappears — its three panels are re-homed where they semantically belong (Advanced → Conversation + Knowledge & Tools; Analysis → Session; Call settings → Channel › Batch calls). “Select agent type” retires in favor of Channel (it never was a type of agent — it’s where the agent is deployed; “Environment” was considered and rejected because it’s the meta-bucket’s name and reads as infra to developers). Header-level utilities (name/ID, Custom config JSON, Import, Deploy CTA) stay global — they operate on the whole agent, not one layer.

Weight checkToday’s builder is 4 steps + 3 optional panels = 7 doors. The new tree is 5 doors, all first-class. Channel’s subsections are mutually exclusive per agent (a phone agent never sees widget or batch subsections), so the effective TOC a user actually reads is ~4 sections × 4–5 rows.

5Deviations from the convention & rules applied

Per the brief: sections were merged, added, or dropped only where the convention didn’t survive contact with what production actually has.

  1. 100% production rule. The tree contains only what ships in studio_x_2 today. Gated builds, type-only fields, and roadmap features are parked in §4 with reserved homes — visible in the register, invisible in navigation.
  2. Nine layers → five sections. Decision & Orchestration and Safety & Governance have zero live items — dropped, not hidden. Memory + Tool Layer merge into Knowledge & Tools (two small pages don’t justify two doors). Execution Runtime reduces to one cross-link row (BYOK credentials) inside Knowledge & Tools — Agora manages sandbox/containers/queues, so there is nothing for a user to configure.
  3. One new section: Channel. Phone numbers, widget embeds, batch dial-lists, and SDK snippets are distribution — none of the nine layers holds them without distortion. It also retires the “Select agent type” label (it’s not a type of agent) and absorbs Call settings. “Environment” was rejected as its name: it’s already the meta-bucket, and developers read it as infra.
  4. Persona splits from voice. The voice editor currently bundles audio identity (Conversation) with personality/tone text (Brain). The IA files them under two homes; the editor UI can keep editing both.
  5. Global utilities stay global. Name/ID, Custom config JSON, Import, and the Deploy CTA operate on the whole agent — they belong to the header, not any section.

6Open tensions — for the improve pass, not this draft

T1 · Widget styling’s true layer

By the convention, widget chrome is “Streaming UI” → Conversation. Kept with its channel so one artifact isn’t split across two pages. Revisit if widget styling ever becomes channel-independent.

T2 · The speed/cost preset spans layers

Fastest/Balanced/Cheapest writes STT + LLM + TTS at once. It lives in Brain › Model but mutates Conversation fields — needs a cross-section affordance in design.

T3 · Where does Review & go live end?

Deploy summary/blockers sit in Channel; draft-vs-live state sits in Session. Same underlying state machine — decide in design whether they share one surface.

T4 · Runtime section resolved v2

Dropped. BYOK credentials are one cross-link row in Knowledge & Tools. Revisit only if credentials editing ever moves into the builder.

T5 · Five doors still need a ramp

The wizard’s strength is a short critical path. The outline view must keep a “what’s required to deploy” ramp (the blockers list already exists) so first-run users aren’t left to wander even five sections.

T6 · “Knowledge & Tools” label

The merge sidesteps the Memory-vs-Tools debate, but the compound label is untested. Tree-test against alternatives (“Resources”, “Capabilities”) before locking.
