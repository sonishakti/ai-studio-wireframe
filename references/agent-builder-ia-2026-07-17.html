2The convention we’re aligning to

Two views of the same model. The three buckets are the meta-grouping — they become the LHS group labels. The layers are the pages under them. Every Agora config item slots into a layer; layers we have nothing for stay in the model but are hidden from v1 navigation (rule 3, §5).

Agent — the brain

Model, system instructions, persona, skills, behavior and reasoning. Plus the layers the brain talks through and remembers with: Conversation, Orchestration, Memory.

Environment — the hands

Runtime/sandbox, files, APIs, MCP servers, permissions, credentials, network. For Agora this is Tools + Runtime — and Deployment, the one section we add (rule 1, §5).

Session — the execution

Connects agent + environment: state, streaming, events, progress, replay, debugging. For Agora: test/talk, transcription, data points, evals, draft-vs-live state.

Navigation behavior (the ask)LHS is an outliner: each section row expands to show the table of contents of its page — every subsection is a link. Clicking a subsection navigates the RHS straight to it; the user never has to scroll the RHS to find anything. This matches the existing scroll-spy rail mechanics — the change is the grouping and the expandable TOC level, not the interaction model.

5Deviations from the convention & rules applied

Per the brief: items were added/removed from a bucket, or a section created, only when something genuinely didn’t fit.

  1. One new section: Deployment. Phone numbers, widget embeds, batch dial-lists, and SDK snippets are distribution, not conversation behavior — none of the nine layers holds them without distortion. It sits under Environment (it is where the agent meets the world) and it protects the product’s north star: go live fast. Batch call window / concurrency / retries stay with the Batch channel (task coherence) rather than scattering into “Decision & Orchestration.”
  2. Layer names kept, two shortened. “Conversation Layer” → Conversation, “Memory System” → Memory, “Tool Layer” → Tools, “Execution Runtime” → Runtime & credentials, “Session Manager” → Session. Same buckets, sidebar-length labels.
  3. Empty sections are hidden, not deleted. Decision & Orchestration and Safety & Governance have zero configurable items today. They stay in the model with reserved homes (§4) and appear in nav the day their first item ships. Rendering empty convention pages would be navigation theater.
  4. Runtime is honest about being thin. Agora manages sandbox/containers/queues; the only user-facing runtime concerns are BYOK credentials and App ID — both live elsewhere and are cross-linked, not duplicated.
  5. Persona splits from voice. The voice editor currently bundles audio identity (Conversation) with personality/tone text (Brain). The IA separates them; the editor UI can keep editing both — it just files them under two homes.
  6. Global utilities stay global. Name/ID, Custom config JSON, Import, and the Deploy CTA operate on the whole agent — they belong to the header, not any layer.

6Open tensions — for the improve pass, not this draft

T1 · Widget styling’s true layer

By the convention, widget chrome is “Streaming UI” → Conversation. Kept with its channel in Deployment so one artifact isn’t split across two pages. Revisit if widget styling ever becomes channel-independent.

T2 · The speed/cost preset spans layers

Fastest/Balanced/Cheapest writes STT + LLM + TTS at once. It lives in Brain › Model but mutates Conversation fields — needs a cross-layer affordance (or a “stack” banner) in design.

T3 · Where does Review & go live end?

Deploy summary/blockers sit in Deployment; draft-vs-live state sits in Session. Same underlying state machine — decide in design whether they share one surface.

T4 · Runtime page vs fold into Tools

Two cross-links may not justify a section. Options: keep (convention-aligned, room for BYOK-in-builder) or fold into Tools until credentials move in.

T5 · Nine sections vs four steps

The wizard’s strength is a short critical path. The outline view must keep a “what’s required to deploy” ramp (blockers already exist) so first-run users aren’t lost in nine doors.

T6 · Knowledge = Memory or Tools?

Mapped to Memory per the convention (vector store / semantic search). Some competitors file KB under Tools. Tree-test this label with users before locking.
