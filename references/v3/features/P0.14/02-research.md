## Per-vendor copy / avoid

**Vapi** — copy: name the save-time consequence in one sentence pinned right at the point of action ("The current version is the configuration used by live calls"), not buried lower on the page. avoid: nothing in Vapi's flow to avoid for this row — the draft/publish split is exactly what the v3 API does not have, so it cannot be built this round; keep it as a named API ask only (already in `more.api`).

**Retell** — copy: Retell's version-number convention (`V2 (draft)` → `V2` on publish, numbers never reused) is a clean naming precedent worth keeping in mind for the eventual "agent versions" API ask. avoid: don't copy the two entry points into Compare (history hover + publish modal) literally — Studio has no version history to hover over yet; a single "Compare before you save" affordance would be premature.

**ElevenLabs** — copy: state a one-way-door decision plainly before it happens (versioning "cannot be disabled" once turned on) — the same honesty P0.14 needs when the API forces every save to reach callers at once, no publish step to opt into. avoid: silent last-write-wins on conflicting saves (no dialog, only an API `force` flag) — Studio's planned P0.14.d (show both versions, let Sam choose) is already stronger than this and should not be watered down to match it.

**LiveKit** — copy: nothing to adopt — the entire flow is CLI-only with no in-product screen to compare against Studio's UI. avoid: gating instant rollback behind a paid plan; Studio has no plan tiers in the v3 spec and revert guidance (P0.14.b) should not become a paywalled feature.

**Vercel (indirect)** — copy: the "Verify the information" step before an irreversible action — restate exactly what changes and what doesn't, in plain sentences, immediately before the single confirm button. This is the direct model for P0.14's save-time line: name the number or run, say plainly that the change reaches it now, then let Sam continue. avoid: Vercel's own stale-config caveats (env vars silently not rolled back) are a warning about *their* rollback, not a pattern to copy — Studio has no rollback at all yet, only a revert-by-hand fallback (P0.14.b).

## Gaps

1. **No vendor shows a save-time warning line on the everyday edit-and-save path itself** (as opposed to a dedicated publish/rollback screen). Vapi and Retell avoid the question entirely by requiring a separate Publish action; ElevenLabs avoids it by making versioning opt-in; LiveKit and Vercel only warn inside a dedicated deploy/rollback flow. Studio's situation — every PATCH reaches callers at once, with no publish step in the v3 API — has no direct UI precedent anywhere in reach; the save-time line and "Sessions since this change" door (P0.14's `more.subtasks`) are original design work, not a ported pattern.
2. **P0.14.c (saves while sessions are running keep their original agent) has no vendor evidence at all.** Vapi's "draft changes do not affect live calls" is the closest adjacent statement, but it describes a draft/publish split Studio does not have. The brief notes "API team to confirm" — still open.
3. **No fixture support yet** for a per-agent version/updatedAt-since-last-test concept in `agent-builder-v3/data.ts` (see Rule 0c) — Design/Build needs this before P0.14.a step 2 (the save-time line) or the P1.3 "Sessions since this change" door can be screenshotted.
4. The competitor Chrome profile (`~/.agora-design/chrome-competitors`) was not used this pass — every finding came from public docs with no sign-in required, so the "still owed" logged-in product captures (an actual Publish button, an actual Compare modal, an actual conflict dialog) remain unseen.
