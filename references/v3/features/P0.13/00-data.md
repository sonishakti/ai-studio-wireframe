## What a new account lacks

Everything this flow shows except the presets: no agent, no session, no test, so the Test tag, the Your tests door and the Sessions hint have nothing to render. The flow therefore starts on a live agent from the demo account; on a brand-new account the same surfaces stay empty until the first test (the door shows only when the registry holds an entry for the agent; empty first).

The v3 API has **no field** that marks a session as a test and **no read** of `client_reference`, so the tag can only come from Studio's own record of the ids it started. There is no `purpose` field, no test flag on `Session` or `SessionListItem`, no transport or channel in any read, and no `client_reference` filter on the list. A test is a session Studio started: the proof is the stored id, nothing else (rainy f is the honest consequence).

Where the record lives: the Console has a server-side Studio store already (the Console backend keeps Studio agents with `properties`, versions, credentials, knowledge bases, MCP servers and resources per app, `src/server/console-backend/studio*.ts`), so the registry's home is a Studio object per app, `studio_tests`, written by the Console server, never by the v3 API. Until that object exists, the port holds the registry in the browser (`localStorage`, key `ng-console:studio-tests:<appId>`), and a cleared browser turns a test into production (.f). Open question 1 asks the owner to confirm the home.

Billing: test minutes are billed and flagged (funnel stage 16), so nothing here says free.
