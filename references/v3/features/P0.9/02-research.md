## Rule 0, data first
a. **Partially.** `agent_frontdesk` is a seeded inbound-type agent that is already `live` with a number connected (`+1 415 555 0142`, "Support line"), so the happy path's *end state* — a number pointed at an agent — is real and URL-reachable today (`/v3?concept=a&view=agent&agent=agent_frontdesk&tab=deploy`). But no inbound-type agent has **zero** numbers: `agent_frontdesk` and `agent_api_untyped` both carry a number already, so P0.9.b's empty state (`EmptyRow`, "No number answers with this agent yet") exists in code but has no stable, URL-reachable fixture to screenshot without first disconnecting a live agent's number.
b. **Outside our accounts:** the four vendors' signed-in dashboards, already captured under `competitors/product/*` and reused below with zero new capture needed. Twilio (this row's indirect) at `research/16-phone-number-purchase/02-research/_docs.md` and `research/17-sip-trunk-setup/02-research/_docs.md`, both desk research from public docs; this session added one product screenshot of Twilio's own SIP trunking doc page to confirm the desk notes against the live page. c. **In our own fixtures, still needed:** (i) an inbound-type agent with zero numbers, reachable by a stable id, so Design can screenshot the "no number yet" empty row without a live click sequence; (ii) once call policy and transfer ship, one inbound agent with them set (gray tick, "you configured this") and one without (no tick), per the empty-first/quiet-chrome rule; (iii) a data-shape decision for "not reached yet" (P0.9.f) — `ProtoAgent.numbers` is today a bare `string[]`, with nowhere to hang a per-number health or last-test-call signal.

## Per-vendor copy / avoid

**Vapi** — copy: nothing fresh this session; see `research/17-sip-trunk-setup` for the prose findings (gateway IP as the allowlist, Telnyx walkthrough). avoid: the credential-only `byo-sip-trunk` model has no dashboard form at all for setting it up — API/curl only — leaving a low-code user no UI path; and our own archive shot of its SIP docs page is a dead 404, worth re-capturing in a future pass if a screenshot is ever needed.

**Retell** — copy: one "+" menu offers both doors ("Buy New Number" / "Connect to your number via SIP trunking") — our own sheet already does this tighter, as two radio options inside one sheet rather than two separate flows. avoid: identity verification ("Identity Verification Required · Powered by Persona") is discovered only by trying to add a number, never disclosed earlier in the journey.

**ElevenLabs** — copy: names its allowlist fields plainly ("Allowed Numbers", "Allowed Source IP Addresses") with an honest stated default ("leave empty to allow all"). avoid: an enterprise upsell banner ("Static IP SIP Servers Available… Contact sales") sits inside the same sheet as the fields a self-serve user is trying to fill in.

**LiveKit** — copy: the only vendor whose product shows a real field-level SIP validation message ("Field 'numbers.0': Empty numbers are not allowed."). avoid: "Create a new trunk" defaults to a JSON editor tab over the visual "Trunk details" tab, pushing developers toward hand-written JSON for a routine setup step.

**Zendesk Talk (Refero, indirect)** — copy: the whole first-session job is one guided, numbered flow that ends on a real simulated inbound call (Accept → Hang up → ticket link), not a saved checkmark — precisely the "ends on a call" shape this row's gap needs, and consistent with the existing A3 rule already on file (`LEARNINGS.md:518`). avoid: the call-readiness card's "online/offline" presence toggle assumes a human agent stepping away from their desk — a voice agent has no equivalent concept, so port the stepper and the end-on-a-call idea, not the presence metaphor.

**Twilio** — copy: every control in this job is a named page in the doc's own nav (Termination settings, Origination settings, Numbers, Codecs, Calls per Second, Call Recording, Secure Trunking) — confirmed live this session, matching the desk research. avoid: nothing new; the fuller critique ("nobody ends setup on a call," "nobody sells a carrier") already stands from the existing desk research.

## Gaps

- No call policy fields (max duration, max silence, four end rules) exist anywhere in the deploy tab or the Connect-a-number sheet today — confirmed by reading `parts/deploy.tsx`: `DeployArea`'s `inbound` branch renders only `InboundNumbers` (the connected-number list) and `ConnectNumberSheet` (the picker/SIP form in shots 6–7). This is the row's largest build gap, not a vendor gap — no vendor in this research has a vendor-native call-policy field either (Retell's concurrency/CPS settings are workspace-level, not per-number).
- No transfer field (an E.164 number plus a trigger) exists anywhere in the current UI, matching `more.api`'s note that transfer is not yet in the v3 API surface for inbound.
- No allowlist / IP field on the SIP path (shot 7), unlike LiveKit's "Allowed addresses", ElevenLabs' "Allowed Source IP Addresses", or Twilio's IP Access Control Lists — worth deciding whether P0.9's build spec should add one now or explicitly defer it in words, per the v3-API-truth rule.
- No "not reached yet" / health signal on a connected number: `ProtoAgent.numbers` is a bare `string[]` today, so P0.9.f's spec ("the row reads Not reached yet") needs a data-shape decision before it can be more than static copy.
- No inbound-type, zero-number fixture reachable by a stable id (Rule 0.c) — Design should either add a third inbound agent fixture or describe the empty state from code (`EmptyRow`, already read) rather than a screenshot.
- Refero has no indexed authenticated screens for any of the four voice-AI vendors' number/SIP pages (repeat of the P0.4 finding for this product category) — its one contribution here is the Zendesk Talk flow, which fills the specific gap the row's `research_brief` named and nothing more; the four vendors' evidence stays product-shots-first, exactly as the row's own `research[]` already recorded.
- `competitors/public-docs/vapi-sip-trunking.png`, the file this row's original research note cites for Vapi's public docs, is a captured 404 in the current archive (shot 10) — flagged here so a later phase doesn't read it as content; nothing in this row depended on it, since `research/17-sip-trunk-setup/_docs.md` already carries the real findings in prose.
