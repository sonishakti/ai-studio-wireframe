# P0.10 Have the agent dial a list of people · JTBD

Track: **v3**. Persona: **Sam, a developer**. Source: `references/v3/03-strategy/prd-v3.json` features[P0.10]. No ClickUp comments on the task, so there are no change notes. Concept A is the surface: the Deployment tab of a batch agent (`tab=deploy`, P0.8), the New run sheet its Go live opens (`NewRunSheet`, `panel=new-run`, P0.3's key), the Runs row that lists each run, and the run panel (`RunSheet`, `run=<id>`) with its Pause, Resume, Cancel and Run again. Scope is this agent's first run and what rides on it: the list, its rejects and the variable mapping, the from number, the calling windows, pacing, call policy, voicemail and session limits, the estimate against free minutes, and what the run says while it dials, waits, pauses, fails or is canceled. Watching runs over weeks is P1 monitoring; the page-level minutes banner and reactivation are P1.7.

## Job step

If the agent will dial a list of people, Sam has the agent reach them only at acceptable times and without overloading the team or the phone lines.

**Job.** Have the agent dial a list of people.
**Situation.** The agent is tested and its prompt names the things it must say per person; a list of 500 patients is in a spreadsheet.
**Sam wants to.** Have the agent remind 500 patients about their appointments.
**So that.** Every patient hears the reminder at a reasonable hour, and nobody at the clinic gets flooded with callbacks at once.

**Job statement.** When my batch agent is ready, I want to upload the list, see which rows are bad and which prompt variables the list covers, say which hours and how fast the agent may dial, and know roughly how many minutes it will use, so the run starts within minutes and reaches every patient at a reasonable hour.

**Why now.** Today's sheet takes a list without reading it (a hardcoded "600 contacts"), maps variables without letting Sam map, offers one datetime window and no weekday hours, caps concurrency with a bare number, says nothing about minutes, and the run panel shows counts but no failure and no Cancel (`shots/before-02-new-run-sheet-empty.png`, `before-03-new-run-sheet-list-mapped.png`, `before-05-run-detail-running.png`). The v3 API now carries `schedule.days`, `pacing.max_calls_per_second`, `transport.call_policy`, `Campaign.failure` and `:pause`, `:resume`, `:cancel` (requirements 7 and 48), and the KPI (7 in 10 batch agents start a run within a week of the first configured test, the first contact reached within 15 minutes of the start) needs the list to be a Go live action, not agent config.

## Happy path · P0.10.a

Story: Sam wants the agent to remind 500 patients about their appointments, so every patient hears the reminder at a reasonable hour.

1. On **Deployment**, with the agent tested and the prompt written (P0.8's Readiness reads two ticks and "A contact list is uploaded in New run."), Sam presses **Go live** in the Runs row. The sheet **New run** opens on **Contact list**. Sam drops `patients-oct.csv`; the sheet reads it and shows `patients-oct.csv · 500 contacts` and the mapping table with `patient_name`, `appointment_time` and `doctor` each matched to the column of the same name. `contact_list_uploaded {rows: 500, rejected: 0, columns: 4, uncoveredVars: 0}`
2. Sam ticks the number to dial from, `+1 628 555 0110 · Spare`. Where a variable had no matching column, Sam picks one from the row's select. (no event; the values ride on the create)
3. Under **When**, Sam keeps **Start now**, ticks **Mon** to **Sat** in **Calling windows**, sets 09:00 to 18:00 in America/Los_Angeles, and reads "Inside a calling window now, so dialing starts at once." Sam opens **Pacing** (10 at once, 3 attempts, 10 min apart), leaves **Call policy** (Leave a message on voicemail, no limits), **Transfer** (None) and **Session limits** (P0.3's defaults) collapsed. (no event)
4. Above the footer Sam reads "About 1,000 min for 500 contacts at 2 min each. 1,800 free minutes left." and presses **Start run**. Studio sends `POST /campaigns` with the contacts, the from number, the calling windows, the pacing and the lifecycle; the toast reads "Run 1 started. Dialing 10 at once from +1 628 555 0110."; the header badge reads Live; the Runs row lists `Run 1 · Sep 26 · Running · 0 of 500`; Readiness's third item ticks with the list name. Two minutes later Sam opens the run and sees Completed 1 and the first session row. `go_live_clicked {deploymentType: batch, estMinutes: 1000, freeMinutesLeft: 1800, contacts: 500, hasWindows: true, scheduled: false, testHeard: true}`, `operation_succeeded {operation: telephony_campaign_create}`, `run_status_changed {to: running, trigger: user}`, `channel_connected {batch}` (server), `agent_answered_production` (server, derived from `counts.completed`)

Done when: `channel_connected {batch}` within 7 days of `agent_tested_configured` and, within 15 minutes of `Campaign.started_at` (median), `counts.completed` of 1 or more.

## Measures

- KPI: Go live rate, batch. `agent_tested_configured` on agents with `deploymentType: batch`, then `channel_connected {batch}` within 7 days, share, 70 % or more. Wall clock `Campaign.started_at` (polled) to `counts.completed` of 1 or more, median 15 minutes or less. The active part, sheet open to Start run, is read from `go_live_clicked` against the sheet's `openedAt` (`wallMs`), the same clock P0.9's `phone_number_linked` uses.
- Counter metric: runs canceled in the first 10 minutes, 10 % or fewer, from `run_status_changed {to: canceled}` against `started_at`. The .d line before the press and the cancel confirm naming the pending count are the two places a needless cancel is caught.
- Assumption under test: treating the list as a Go live action lifts batch Go live against the current Console's campaign flow; kill below 50 %.
- Events: `contact_list_uploaded {rows, rejected, columns, uncoveredVars}`, `go_live_clicked {deploymentType: batch, estMinutes, freeMinutesLeft, contacts, hasWindows, scheduled, testHeard, repeat, wallMs}` (batch fires it at Start run or Schedule run, not at the sheet's open; P0.8's inbound firing is unchanged), `go_live_blocked {codes: batch_uncovered_vars | list_no_phone | no_list | no_number}`, `run_status_changed {to, trigger: user | api | window | billing}`, `operation_succeeded {operation: telephony_campaign_create | telephony_campaign_interrupt}` (in 2.1.0), `operation_failed {operation, code, reason}`, `rejects_downloaded {rejected}` (new; not in the PRD's list, added so the reject download can be counted), `cta_viewed {cta: add_card}`, `external_link_opened {surface: billing}`; `channel_connected` and `agent_answered_production` are server events.
- API: Ready for the list, the from numbers, the windows by weekday, the dial rate, the attempts and backoff, the call policy with voicemail and end rules, the transfer, the lifecycle, the failure, and pause, resume and cancel. Missing: returned contacts (.i), a next-dial field (.d, computed by Studio), a pause reason (.g, inferred by Studio from billing), free minutes and the card (G9, billing outside v3), an estimate (Studio's arithmetic), `data_policy` on a run (P0.8.d).
