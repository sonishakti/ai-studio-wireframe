# P0.10 · Have the agent dial a list of people — research

## Rule 0, data first

**a. Does a new logged-in account show the data this flow needs?** Partly. `agent_survey` (Batch, Draft) shows a real empty Runs state and a real **New run** sheet — CSV upload, the prompt-variable-to-list-column mapping table, the from-number checkboxes, When (start now / one datetime window), and a collapsed "Pacing, retries and voicemail" panel (calls at once, attempts per contact, on-voicemail) — so most of the happy path already renders on real fixture data, not a mock. `agent_payments` (Batch, Live) adds a real three-run history and a real run-detail panel with live counts (Pending/Calling/Completed/Failed/Canceled), a per-session table, and Pause/Run again. But nothing in the fixtures shows: a rejected-rows count or a reject download (the CSV "upload" is a stub — clicking the dropzone just sets a hardcoded filename and a hardcoded "600 contacts", nothing is parsed or validated); a run-level failure with a code/provider/message (`RunStatus` already has `"failed"` and `"canceled"` in its type, `data.ts`:23-29, but no seeded run uses either — only one per-session outcome is `"failed"`, in Run 3's Sep 24 session table); calling windows **by weekday** (When only offers a single start/end datetime + timezone, never a weekly recurrence); or any minutes/free-minutes figure. Every gap the JTBD's rainy list names is real, not fabricated, but five of nine rainy ids (`.b`, `.e`, `.f`, `.g`, part of `.d`) have no fixture to screenshot from at all yet.

**b. Where it exists outside our accounts:** Vapi's own dashboard is signed out this session (confirmed again — every `dashboard.vapi.ai` URL redirects to login); its public docs are open and already the basis of this repo's own desk research (`v3/02-research/batch-retention-experiments.md` §1, `research/18-channels/merger-v3/report.md`). Re-read this session at `docs.vapi.ai/outbound-campaigns/quickstart` to confirm those quotes still hold and to capture one shot the desk notes describe but never screenshotted (the Max Concurrency slider). Retell and ElevenLabs are both already `Done` in this row's own research table with product shots on file, including ElevenLabs' empty batch list (rainy, already marked) and Retell's dashboard login-gated on the research profile (`retell-18m-batchcall-login-blocked.png`) — per the automation contract only vendors still `Not started` get a fresh pass this run, so both are reused, not re-captured. Bland (indirect) has no prior shots anywhere in this repo; captured fresh from public docs this session, since Bland's own dashboard needs a sign-in this session does not have. Refero MCP surfaced no voice-AI batch-calling screen at all, but did surface two directly usable analogs outside the category: Cake Equity's CSV-import validation-error screen and Reclaim AI's per-weekday hours chips — used as indirect precedents the way P0.8 used Stripe's activation review.

**c. What must exist in our own fixtures:** (i) real CSV parsing with a rejected-rows count and a download, so P0.10.b has something to show — today the New run sheet's upload is a stub; (ii) a seeded run in `"failed"` or `"canceled"` status (not just a per-session outcome) carrying a failure code, provider and message, for P0.10.e; (iii) a weekly recurrence control on When, for happy step 3 — the current sheet only offers one datetime window with a timezone, never "Tue/Thu 9–5"; (iv) an estimated-minutes-vs-free-minutes-left figure and an Add card affordance for P0.10.f/g — grepped the whole `agent-builder-v3` prototype for `freeMinutes`, `estMinutes` and `Add card`; none exist anywhere, confirming the PRD row's own KPI event names (`go_live_clicked {estMinutes, freeMinutesLeft}`) have no UI or fixture behind them today; (v) a `lifecycle` concept on a run (P0.10 happy step 3 names it) — no such field exists on `Run` in `data.ts` today, only `schedule`, `maxConcurrent`, `from`.

## Per-vendor copy / avoid

**Vapi** — copy: Max Concurrency is a slider with the organisation-wide ceiling stated inline ("The upper bound is your organisation's concurrency limit") rather than a bare number field with no visible cap — worth matching for our own "Calls at once" input. avoid: the contacts preview hides every column except name and number while still using them as variables underneath — Sam would have no way to see what the agent will actually say; our own variable-mapping table (shot 3) already does better and should not regress toward Vapi's blind preview.

**Retell** — copy: reserved CSV columns are named in plain words at the point of upload (`ignore e164 validation`, `override agent id`, `override agent version`) rather than buried in a separate schema page — a good precedent for surfacing E.164 rejection at the point Sam sees the row, not after. avoid: batch calls never touch the Do Not Call flag on a matching contact, even though Retell has one — a boundary we should not repeat if Agora ever joins its own contact/CRM object to a batch run.

**ElevenLabs** — copy: the empty batch-calling state is exactly one sentence and one button, no seeded rows, no chrome — already the shape our own before-01 shot has, worth keeping as the target for every future empty state on this tab, not just this one. avoid: batch calling is gated behind a channel picker (Telephony/WhatsApp) before the actual create form appears, and Zero Retention Mode is flatly incompatible with batch calling with no inline warning at the point of turning either on — two extra decisions or a silent conflict we should not add.

**LiveKit** — copy: nothing to copy for batch specifically; it has no batch product, only per-session dispatch (same finding as P2.5). avoid: n/a.

**Bland (indirect)** — copy: a three-way batch status split — done, partially done (with its own name, "Completed Partial"), failed outright — each with a one-line plain-English definition, is the cleanest precedent found for P0.10.e's "failure code, provider and message" without over-building a status taxonomy. avoid: invalid rows are only "reported in the error logs," a separate surface from the create screen and from the batch's own status — Sam has to go looking for the reject list rather than seeing a count next to the upload the way Cake Equity's inline banner (shot 6) shows it.

## Gaps

1. **No vendor in the set (direct or indirect) shows a reject *count* next to the upload itself.** Bland reports invalid rows only in a separate error log; Retell and ElevenLabs' docs describe reserved/required columns but neither vendor's batch list was reachable populated this session to confirm what a rejected-row moment looks like live. Cake Equity (shot 6, outside the category) is the closest usable precedent for P0.10.b's "the rejected count shows, and Sam can download the rejects" — this is original design work with a cross-category precedent, not a same-category one.
2. **Retell's and ElevenLabs' product batch lists remain unverified live this session**, same caveat the PRD row's own note already carries (empty on 23 Sep) — both are `Done` per the automation contract's reuse rule, so this run did not attempt a fresh sign-in; a future pass that finds either workspace populated should recapture the happy states (populated list, create form, detail page) the prior pass's own report.md logged as "not captured."
3. **No fixture anywhere in `agent-builder-v3` has a run in `"failed"` or `"canceled"` overall status**, only the `"failed"` per-session outcome used once (Run 3, Sep 24). Design and Build need a seeded failed-or-canceled run, with a failure code/provider/message, to screenshot P0.10.e honestly — nothing to fabricate around, `RunStatus` already has the type, just no seed uses it.
4. **`estMinutes`/`freeMinutesLeft` have no UI or fixture anywhere in the prototype today**, confirmed by grep, despite being named as new client events in the PRD row's own KPI block. P0.10.f ("Add card shows, starting is still allowed") and P0.10.g ("account is suspended... minutes banner offers Add card") are both entirely new surfaces with no competitor precedent found either — every vendor researched treats concurrency/minutes as an account-wide setting or limit, never a per-run estimate shown before starting (Vapi's Max Concurrency slider, shot 10, is the closest analog and it is a cap, not a cost estimate).
5. **No vendor documents what happens when calling windows are closed and Sam starts now anyway (P0.10.d)** — Retell, ElevenLabs and Vapi's docs all describe scheduling as a single window or "send now," none address a start-now-outside-window collision. This is a genuine gap with no precedent to lean on; the PRD row's own recovery text ("status stays running... next dial time computed from schedule.days") will need to be designed without a reference.
