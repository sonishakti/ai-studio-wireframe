# P0.5 · Connect other systems to the agent — research

## Rule 0, data first

a. **Mostly yes, one fixture gap.** `agent_payments` already carries a populated "Knowledge and tools" row (`Billing FAQ` knowledge base + `send_payment_link` tool), so the happy path renders with real-looking data today. `agent_survey` has `context: []`, so the true empty state ("The agent answers from its prompt alone.") is also reachable with zero setup. What is missing: the MCP "Connect" action and the Function tool "Add" action have no failure branch in the fixture — Connect always succeeds and always returns the same four tool names (`search_orders`, `get_customer`, `create_ticket`, `refund_order`) no matter what endpoint is typed, and there is no row-level state for "Not checked" vs "Failed in last test · <time>" (P0.5.b/.c/.d/.i need this to be screenshot-able in Build).
b. **Outside our accounts:** Vapi's dashboard is signed out and the owner rule is never to sign in, so its product forms stay evidenced only by its public docs (existing desk research plus one new capture below — the Troubleshoot tools page, since the dashboard itself is unreachable). Retell, ElevenLabs and LiveKit's signed-in product screens were already captured in prior research (`competitors/product/*`) and are reused untouched. Refero MCP was searched for the specific gaps (queries: "tool configuration error", "integration failed", "MCP server connection error", "knowledge base upload failed", "connection test failed", "file too large upload error", "webhook test failed timeout", "API key expired unauthorized") — none of the ~4,000 combined results were a signed-in Vapi/Retell/ElevenLabs/LiveKit screen, but Zapier, n8n, Make, Manus, TwelveLabs, Glorify and HTTPie all surfaced strong generic analogs for the indirect competitor and for validating common failure-UI conventions (error banner + reason code + a named recovery action).
c. **In our fixtures, still needed for Design/Build:** (1) a way to make "Connect" fail or return zero tools, for P0.5.b; (2) a row-level "Not checked / Failed in last test · <time>" state visible without opening the sheet, for P0.5.c/.i; (3) upload validation on the knowledge base sheet (today: a name field and a drop zone, nothing else — no progress, no size limit, no rejection), for P0.5.g; (4) a flag to gate the "Knowledge base" menu item, since it appears unconditionally today, contradicting P0.5.g's "sits behind a flag" requirement.

## Per-vendor copy / avoid

**Vapi** — copy: the Troubleshoot page's four named symptom categories ("Tool won't trigger", "No result returned", "Response ignored", "Parameters cut off") are ready-made, plain-language rainy-state labels. avoid: tools are workspace-wide by default, which is out of scope — P0.5 stays "this agent's integrations" per `more.req`.

**Retell** — copy: the "Ignore the notice, re-add after fixing the cause" recovery pattern for a partially-failed knowledge base is the one real precedent to build P0.5.g's error states on. avoid: splitting Functions, Knowledge Base and MCPs into three separate accordion rows plus a fourth workspace Integrations page — four surfaces for one job is more doors than P0.5's single "Knowledge and tools" list should ever have.

**ElevenLabs** — copy: a required trust checkbox plus a Test Connection button before an MCP server can be saved. avoid: applying that same test door only to MCP and leaving webhook (function) tools untested — P0.5's row treats "saved" and "tested" as different states for every kind, not just MCP.

**LiveKit** — copy: the Silent toggle on an HTTP tool (hide the result from the agent, no spoken response) is a small, real control worth considering later. avoid: the MCP form's total silence on limits — no timeout, no tool allowlist, no test — is the sparsest of the four and not something to match.

**Zapier (indirect)** — copy: naming the exact failure, showing the raw reason string, and offering more than one recovery action (troubleshoot vs. skip) on the object that failed. avoid: Zapier's failure card blocks the whole step until resolved or skipped; P0.5.d's agent should keep answering without the tool rather than stopping the session.

## Gaps

- Vapi's live dashboard Tools/MCP forms remain uncaptured this session — the product is signed out and the owner rule is never to sign in. `vapi-assistant-model.png` (Tools tab, not opened) plus the Troubleshoot docs page are the closest evidence available; Vapi stays "Partial" until a signed-in capture is separately authorized.
- No vendor's product screenshots or public docs (Vapi, Retell, ElevenLabs, LiveKit all checked directly this session) show an unreachable-MCP-server or a live tool-call-timeout screen. Zapier's step-error card is the only real on-screen analog found for P0.5.d/.i, and it is an indirect, non-voice-AI product — Design is working from first principles for the exact wording, same as P0.4 flagged for its own undocumented rainy states.
- LiveKit's Agent Console names an "Errors" event type in its Events pane (confirmed via docs fetch) but nothing shows what that looks like on screen — an unresolved blind spot shared by the whole market, not just LiveKit.
- P0.5.e (write-only header, re-enter to change) and P0.5.f (tools unavailable on a realtime pipeline) have no vendor visual precedent in this pass; both are policy/API-driven states to design from the API spec and copy rules directly, not from a competitor screen.
- The prototype's own MCP "Connect" and knowledge-base "Add" flows have no failure branch today (before-04, before-06) — Build will need new fixture logic or URL states before P0.5.b, .c, .d, .g and .i can be screenshotted in the Build phase.
