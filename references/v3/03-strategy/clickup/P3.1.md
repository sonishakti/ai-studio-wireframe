## Job to be done (Sam, a developer)
**Job:** Replace keys without breakage · job map stage **Modify** (Sam adjusts without breaking what runs)
**Umbrella job (P3):** Sam wants to look after everything the team's agents share, by hand or from code, and get the same result either way.
**Situation:** Across the team's agents, Sam replaces or retires a provider key without breaking any agent that uses it.
**Sam wants to:** rotate a leaked LLM key
**So that:** every agent keeps answering with the new one

### P3.1.a Happy path (this is what Sam does)
1. Sam opens Secrets; each set shows its key names, updated date and used by (agents Studio wrote, from labels.studio_secret_sets, and numbers).
2. Sam picks the set and chooses Replace value on the key; the sheet asks for the new value only and reveals nothing.
3. Studio compares key names with the saved set; nothing an agent references is missing, so Save sends PUT.
4. The row shows the new updated date, and Studio offers a test on one agent that uses the set.
5. Sam hears that agent answer; the rotation is done.

### Rainy paths (each needs its own state in the prototype and a frame in Figma)
*   **P3.1.b** Sam deletes a set an agent still uses: The server refuses (409, the detail names one agent in text). Studio lists every agent and number it knows uses the set, adds 'API-created agents may also use it', and keeps the set.
*   **P3.1.c** Sam's replacement drops a key an agent references: PUT swaps the whole set, so Studio diffs key names first and blocks Save until Sam re-points the agent or confirms.
*   **P3.1.d** Sam finds a set Sam never made by hand: Sets the builder made carry the chip 'Created by agent Support desk' from the set name. If that agent is deleted the chip reads 'Agent deleted' and the set stays.
*   **P3.1.e** Someone saved the set while Sam was typing (412 stale ETag): The sheet reloads key names and keeps the values Sam typed; Sam saves again.
*   **P3.1.f** Sam needs to check a stored value: Values are write-only: the row shows key name and updated date, and the only action is Replace value.
*   **P3.1.g** The new key is wrong or revoked: The spec has no key check, so a saved key is not a working key. After Save, Studio offers a test on an agent that uses the set; byok_key_failed names the module that failed.
*   **P3.1.h** Sam has no secret sets yet: One line says sets are made here or when Sam pastes a key in the builder, plus Add secret set.
*   **P3.1.i** The network drops during Save: The sheet keeps key names and typed values and offers Retry. PUT is one request, so the set is either the old one or the new one.

## Goal (KPI)
**In one line:** Replacing a secret key breaks zero agents.
*   Metric: Safe secret replace
*   Target: 0 agents broken by a secret replace; API-created agents reported as unknown coverage
*   How we measure: operation_succeeded {secret_set_replace} to session_ended {status failed, errorCode provider_auth} (G2) or byok_key_failed within 24 h on agents in labels.studio_secret_sets for that set, count of agents per replace (secret_replace_broke_agent). Blocked on G2; interim: byok_key_failed in tests only.
*   Counter-metric: Secrets page visits per new agent ≤ 0.2: keys belong in the builder, not a detour here
*   Assumption we are testing: A used-by list makes write-only keys safe for Sam to manage. Method: derived check after every PUT. Kill: any broken agent adds a replace confirm step.
