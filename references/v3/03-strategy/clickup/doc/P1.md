# P1 Monitoring · Agents

**Job:** Keep every agent working for people outside the team
**Situation:** Agents are live and people outside the team talk to them every day.
**Sam wants to:** know how each agent is doing and fix what fails
**So that:** customers never notice a failure first

**Done looks like:** Sam spots the agent in trouble, reaches the cause in under a minute, removes it and sees the error stop, without losing place.

**Goal:** Median path from a new error to its cause is at most 4 steps and under a minute.

## P1.1 · Know whether an agent needs attention
ClickUp card: https://app.clickup.com/t/868m9wg6k · design ETA Tue 29 Sep · lock ETA Thu 1 Oct

### Job to be done (Sam, a developer)
**Job:** Know whether an agent needs attention · job map: Monitor
**Situation:** Sam finds out whether an agent needs attention right now.
**Sam wants to:** know whether the support agent is fine this morning
**So that:** Sam can either move on or act at once
**Part of P1 Monitoring · Agents:** Keep every agent working for people outside the team

#### P1.1.a Happy path: what Sam does
1. Sam opens the agent from Agents; the agent page opens on Overview with tabs Overview, Analytics, Logs and diagnostics, and Runs when the agent has at least one run.
2. The header reads name, deployment type, deployment status, sessions in range, '2 error groups · 3 warning groups' and the last change.
3. Running now shows what the agent is handling at this moment (built in P1.2).
4. '1 new since 14:02 change' tells Sam whether the last edit brought a new error.
5. Sam clicks the error count and lands on Logs and diagnostics with the same range and severity.
6. Doors stay in the header: Edit agent, Talk to agent (P1.2), Sessions and 'Sessions since this change'.

#### Rainy paths: when it goes wrong
*   **P1.1.b** Errors cannot be read (stream not wired): Header reads 'Errors unavailable', never 0; the Logs door stays and says why it is empty.
*   **P1.1.c** Sessions are not linked to the agent yet (G4): Sessions count reads 'Not linked yet', never 0, with a door to all sessions.
*   **P1.1.d** No production session yet: Counts are hidden; deployment status leads and names the next missing step (P1.8).
*   **P1.1.e** Link opens a deleted agent or one Sam cannot access: Not-found state names the reason, with a link to Agents.
*   **P1.1.f** No warnings can be derived yet: Warning count is hidden, not shown as 0, until an event type carries a warning.
*   **P1.1.g** Agent changed through the API, so Studio has no change time: Header falls back to updated_at and labels it 'Last saved', not 'last change'.
*   **P1.1.h** History shows more sessions than the agent counts: A note says tests and ephemeral sessions are left out of agent numbers.
*   **P1.1.i** Counts load slowly: Each count shows a skeleton; name, status and doors work first.

### Goal (KPI)
**Half of agent page visits with an error end in the error group opened.**
*   Metric: Error badge follow-through
*   Target: ≥ 50 % of agent page visits with an open error group
*   How we measure: agent_page_opened {errorState: errors} to error_group_opened in the same visit (visitId, 30 min inactivity), share of those visits
*   Counter-metric: Badge opens that leave Logs in under 5 s ≤ 30 %
*   Assumption: A count in the header sends Sam to Logs and diagnostics more reliably than a colored state. Method: cohort read; kill below 30 % follow-through.

## P1.2 · Reproduce a surprising session
ClickUp card: https://app.clickup.com/t/868m9wg7e · design ETA Wed 30 Sep · lock ETA Fri 2 Oct

### Job to be done (Sam, a developer)
**Job:** Reproduce a surprising session · job map: Locate
**Situation:** Sam reproduces a surprising session to confirm the problem before changing anything.
**Sam wants to:** hear the odd reply a customer reported
**So that:** Sam can confirm the reply before changing anything
**Part of P1 Monitoring · Agents:** Keep every agent working for people outside the team

#### P1.2.a Happy path: what Sam does
1. Overview lists Running now (start time, ticking duration), then Recent sessions (production), 20 rows, with 'All sessions' and 'Your tests (n)'.
2. A row opens the session panel over Overview; the list stays underneath.
3. Sam clicks Talk to agent; a bubble on the P0.7 voice component connects and Sam hears the first answer with the transcript as it runs.
4. The bubble says 'Test session, left out of this agent's numbers' and links to the test session.
5. The same bubble opens from session detail and from the builder.

#### Rainy paths: when it goes wrong
*   **P1.2.b** Nothing is running: 'No sessions running', with Recent sessions below.
*   **P1.2.c** Sessions are not linked to the agent yet (G4): 'Sessions for this agent arrive when the API links them', with a door to all sessions; Sam's own tests still list from the Studio session registry.
*   **P1.2.d** Talk is refused (AccountSuspended, ResourceQuotaLimitExceeded, ConcurrencyLimitExceeded): The bubble names the reason, one fix and Retry.
*   **P1.2.e** Microphone is blocked: Steps to allow it in the browser, plus a text simulation in the builder.
*   **P1.2.f** Test session drops mid-conversation (network): The bubble says the session ended, keeps the transcript so far and offers 'Talk again'.
*   **P1.2.g** Sam has unsaved edits in the builder: Talk uses the saved agent and names its last-saved time, so Sam knows which version answered.
*   **P1.2.h** No production session yet: Recent sessions shows one line and a door to the deployment strip (P1.8); 'Your tests (n)' stays.
*   **P1.2.i** A recent session has no content (zero retention or expired): The row stays with its tag; the panel says 'Zero retention' or 'Expired', never an empty transcript.

### Goal (KPI)
**4 in 10 talk to agent sessions end in an agent change or the error stopping within a day.**
*   Metric: Talk to agent follow-through
*   Target: ≥ 40 % of Talk to agent sessions
*   How we measure: talk_to_agent_started to agent_updated or error_group_quiet on that agent within 24 h, share of talk_to_agent_started. error_group_quiet (derived): no new occurrence of the group for 24 h; needs G11.
*   Counter-metric: agent_reverted within 24 h ≤ 10 %. agent_reverted (derived): an agent_updated whose changed fields return to their values before the previous agent_updated, within 24 h.
*   Assumption: Sam reproduces a surprise from the agent page and then fixes it. Method: cohort read; kill below 20 %.

## P1.3 · Tell whether an agent change helped
ClickUp card: https://app.clickup.com/t/868m9wg8u · design ETA Wed 30 Sep · lock ETA Fri 2 Oct

### Job to be done (Sam, a developer)
**Job:** Tell whether an agent change helped · job map: Monitor
**Situation:** Sam finds out whether a recent change made the agent's sessions better or worse overall.
**Sam wants to:** know whether Tuesday's greeting change made sessions better
**So that:** Sam can keep the change or undo the change
**Part of P1 Monitoring · Agents:** Keep every agent working for people outside the team

#### P1.3.a Happy path: what Sam does
1. Sam opens Analytics; one range (P1.10) and filters (run, status) drive count tiles (sessions, minutes, status mix) and a sessions-per-bucket chart.
2. The last change is marked on the chart.
3. Sam clicks a tile; session history opens with the same range, filters and env=production.
4. Sam clicks a bucket; the list narrows to that bucket with 'Back to 7 days'.
5. Latency, success and Analysis tiles read 'Arrives with session analytics'.
6. A door opens Logs and diagnostics for the same range.

#### Rainy paths: when it goes wrong
*   **P1.3.b** Sessions are not linked to agents yet (G4, G12): Tiles say 'Arrives when sessions link to agents', never 0.
*   **P1.3.c** Session analytics are deferred: Latency, success and Analysis tiles say 'Arrives with session analytics', never 0.
*   **P1.3.d** Fewer than 20 sessions in range: Counts only, no percentages.
*   **P1.3.e** Paging stopped early: The tile and the list it opens both say partial.
*   **P1.3.f** No Analysis fields defined: The success tile links to the Analysis definition (P1.9).
*   **P1.3.g** Tests, zero retention and ephemeral sessions in the range: Tests excluded, zero retention counted, ephemeral never counted; a note says which.
*   **P1.3.h** Range longer than the API can look back: Presets stop at 30 d until the lookback limit is known; a longer custom range says so.
*   **P1.3.i** No change time recorded (agent edited through the API): The marker uses updated_at and is labelled 'Last saved'.

### Goal (KPI)
**4 in 10 tile clicks open the session behind the number, in the same visit.**
*   Metric: Number to sessions
*   Target: ≥ 40 % of tile clicks reach session_opened in the same visit; 100 % of counts are links or carry a disabled reason (audit)
*   How we measure: tile_clicked to session_opened in the same visit, share of tile_clicked. Bucket clicks are reported apart.
*   Counter-metric: countShown vs the landed list's row count differing by more than 5 % without a partial notice ≤ 10 %
*   Assumption: Counts that open their sessions make the tab useful. The job itself (did the change help) is not measured directly; drill-through is the proxy. Method: cohort read; kill below 20 %.

## P1.4 · Find what fails in an agent and why
ClickUp card: https://app.clickup.com/t/868m9wga0 · design ETA Wed 30 Sep · lock ETA Fri 2 Oct

### Job to be done (Sam, a developer)
**Job:** Find what fails in an agent and why · job map: Locate
**Situation:** Sam finds out what is failing and why, so each cause is fixed once, not session by session.
**Sam wants to:** the cause behind '2 error groups' on the agent
**So that:** Sam can fix the cause once instead of chasing six sessions
**Part of P1 Monitoring · Agents:** Keep every agent working for people outside the team

#### P1.4.a Happy path: what Sam does
1. Logs and diagnostics (agent tab /agents/:id/logs, project view /logs) lists groups '<module> · <event type>' with severity, sessions, first and last seen, a sparkline and tags New, Quiet, Returned, New since change; every cell is a link.
2. Sam opens a group; the panel shows count over time with the last-change marker and 'Since your change: N occurrences'.
3. Sam steps through the affected sessions one by one; a sample line shows the failing log line.
4. Doors lead to the setting, secret set, integration, run or number (P1.6), plus 'View all N sessions'.
5. A separate tests line links to test sessions, kept apart from production.
6. The project view adds 'No agent' and 'Agent not linked' buckets and groups from deleted agents.

#### Rainy paths: when it goes wrong
*   **P1.4.b** No errors in range: 'No errors since <date>'.
*   **P1.4.c** Error stream unavailable: 'Errors unavailable', never 'No errors'.
*   **P1.4.d** Failure with no session (session never created, billing, number): 'No session' rows in the project view with a door to the number or billing.
*   **P1.4.e** A run failed: Campaign.failure shows as one group, linked to the run.
*   **P1.4.f** No stable error code: Key <module_name>:<event_type>, marked approximate; warnings hidden while none can be derived.
*   **P1.4.g** Errors from a deleted agent: The group stays in the project view, tagged 'Agent deleted'; doors are disabled with the reason.
*   **P1.4.h** A group key changes after a code update: The old key redirects to its successor; links keep working.
*   **P1.4.i** Session content not kept (zero retention or expired): The count stays; the sample line reads 'Zero retention' or 'Expired', never empty.
*   **P1.4.j** A fixed error comes back: Tag Returned, listed first, with 'Since your change: N occurrences'.

### Goal (KPI)
**Median path from an error to its cause is at most 4 steps and under a minute.**
*   Metric: Error to root cause
*   Target: Median ≤ 4 steps and ≤ 60 s (p75 ≤ 6 steps and ≤ 120 s). Details: acknowledgement median ≤ 24 h.
*   How we measure: Per visit (visitId, 30 min inactivity): first error_badge_clicked or error_group_opened to first log_line_opened {severity: error} in that group's session; steps = monitoring_pivot count, seconds = delta, median over visits that reach it. Acknowledgement (PRD): first session_ended {status failed} or new error group to error_group_opened or logs_opened for that agent, median. Blocked on the RTM stream (G11) and session_ended (G2); interim: v2 debugging has_error.
*   Counter-metric: Log line left in under 5 s ≤ 30 %; groups unopened at 7 d ≤ 10 %
*   Assumption: Grouping by cause with a one-step path to the failing line beats a flat list. Method: moderated 5-owner baseline on the current Console; kill if the median exceeds 8 steps or 3 min.
