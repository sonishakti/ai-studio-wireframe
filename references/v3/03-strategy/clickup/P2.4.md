## Job to be done (Sam, a developer)
**Job:** Keep and share proof · job map stage **Conclude** (Sam wraps up or hands on)
**Umbrella job (P2):** Sam wants to find out what happened in a session, or in a set of sessions, and why.
**Situation:** Sam keeps or hands on the exact session or view, so support or a teammate sees what Sam sees.
**Sam wants to:** support to see exactly what Sam sees
**So that:** the fix starts without a back-and-forth

### P2.4.a Happy path (this is what Sam does)
1. Sam opens the session full screen; turn, line, t and in= stay in the URL.
2. Copy link writes an absolute range (URL state from P1.10), so the recipient opens the same session and moment.
3. Download saves JSON with the log lines, plus audio when a recording exists.
4. From the list, Export saves a CSV with the active filters.

### Rainy paths (each needs its own state in the prototype and a frame in Figma)
*   **P2.4.b** The session is older than 30 days: 'Older than 30 days, not available'; the row and its metadata stay.
*   **P2.4.c** Sam downloads a zero retention session: The file holds metadata only and says so.
*   **P2.4.d** The export is over the row limit: First rows only, with a notice to narrow the filter; never a silent cap.
*   **P2.4.e** The recipient has no project access: A request-access state with no data; links reach project members only.
*   **P2.4.f** Sam copies a link while the range is relative ('last 7 days'): Copy link converts it to an absolute range, so the recipient sees the same rows.
*   **P2.4.g** The recording is still processing at download: The JSON downloads now and says the audio arrives when processing ends.
*   **P2.4.h** The export runs on a partial API filter: The CSV says 'partial: first N pages', like the list.
*   **P2.4.i** Sam's role cannot see content: The download holds metadata only, with the reason.

## Goal (KPI)
**In one line:** 95 in 100 shared links open the exact session and moment.
*   Metric: Link lands
*   Target: ≥ 95 %. Details: 60 % of session tickets carry a link, once the ticket system and tag owner are named; until then the reopen rate is tracked.
*   How we measure: shared_link_opened {access: ok, found: true, rangeKind: absolute} / shared_link_opened. Reopen proxy: link_copied {object: session} followed by shared_link_opened by a different userId within 7 d, share of link_copied.
*   Counter-metric: No-access landings ≤ 5 %; link_copied {rangeKind: relative} = 0
*   Assumption we are testing: A copyable link and a download replace screenshots; the average Sam shares a session with support once or twice a week. Kill below 30 % reopen at 4 weeks.
