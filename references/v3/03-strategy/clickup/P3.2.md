## Job to be done (Sam, a developer)
**Job:** Route every number to an agent · job map: Monitor
**Situation:** Sam makes sure every number the team owns reaches the right agent.
**Sam wants to:** check the support number after moving agents around
**So that:** every inbound session reaches the right agent
**Part of P3 v3 mapping:** Look after what all the team's agents share

### P3.2.a Happy path: what Sam does
1. Sam opens Numbers; each row shows the number, description, inbound agent and the runs that use it as from.
2. Sam chooses Add number and fills SIP protocol, host, port and allowed IPs; the SIP password is saved as a secret reference and never shown.
3. Sam picks the inbound agent and saves; channel_connected (inbound) fires for that agent.
4. The row now names the agent; Sam dials the number and hears it answer.

### Rainy paths: when it goes wrong
*   **P3.2.b** A number has no agent and no run dials from it: The row warns 'No agent: inbound sessions fail'; a filter pins these rows first.
*   **P3.2.c** Sam points a number another agent holds: A confirm names the agent that loses its inbound deployment before Save.
*   **P3.2.d** Sam deletes a number a scheduled or running run uses: Delete is blocked; the message names the run and links to it.
*   **P3.2.e** The number already exists (409) or the SIP host is wrong: Inline error on that field from ErrorResponse.reason; the other fields keep their values.
*   **P3.2.f** Sam has no numbers yet: One line plus Add number; carrier setup docs are linked because the spec has no number purchase.
*   **P3.2.g** The trunk is down or the SIP login is wrong: The API has no status or trunk health, so the row claims nothing it cannot know. It asks Sam to dial the number and hear the agent (first-week states, P1.8); trunk health is raised as an API ask.
*   **P3.2.h** The secret behind the SIP password was replaced or removed: The row warns and links the secret set (P3.1).
*   **P3.2.i** Sam has hundreds of numbers: The list pages by cursor (GET /numbers) and searches by number, description or agent.

## Goal (KPI)
**No phone number goes more than 7 days without an agent to answer it.**
*   Metric: Unassigned numbers
*   Target: 0 numbers without inbound.agent for > 7 d, excluding numbers used as a run's from number in the last 30 d
*   How we measure: Daily snapshot of GET /numbers stored by Studio (the API has no updated_at). A number counts once it has had no inbound.agent in 7 consecutive snapshots, minus numbers that are a run's transport.from in the last 30 d (number_unassigned_7d, derived). First read on day 8.
*   Counter-metric: Numbers re-pointed within 24 h of Go live ≤ 10 % (number_reassigned; re-points made through the API are not covered)
*   Assumption: Seeing the agent on every row lets Sam catch a dead deployment. Method: compare accounts that open Numbers within 14 d with those that do not. Kill: no difference in unassigned numbers.
