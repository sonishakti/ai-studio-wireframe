## Job to be done (Sam, a developer)
**Job:** Confirm people reach the agent · job map: Confirm
**Umbrella job (P1):** Sam wants to know how each agent is doing with people outside the team, and fix what fails before customers notice.
**Situation:** Once the agent is open to people outside the team, Sam confirms they are reaching it and getting answers. This step proves the P0 outcome.
**Story:** Sam pointed a number at the agent yesterday and wants proof that outside contacts get answers, so Sam can tell the team it works.

### P1.8.a Happy path: what Sam does
1. The deployment strip on Overview shows items per type: inbound number chips (every number pointing here), the latest batch run, or the first code session; each is a door.
2. Three steps follow: deployment on (dated when Studio recorded Go live), first production answer, first proven session.
3. Each step fills as it happens; the next missing step is named.
4. Sam clicks a number chip to open the number, or the run to open the run.

### Rainy paths: when it goes wrong
*   **P1.8.b** No production answer 3 days after Go live: Checks per type: number points here, trunk, keys, calling window, snippet.
*   **P1.8.c** Only Sam has reached the agent by day 14: 'No outside contacts yet', marked provisional.
*   **P1.8.d** Production sessions drop to 0: Checks keys, number and suspension.
*   **P1.8.e** A number was pointed at another agent: The strip names the number and where it points now.
*   **P1.8.f** API-only account (Studio never recorded Go live): Steps undated and marked provisional.
*   **P1.8.g** Batch agent, turn count not available (G2): The proven step says it waits for turn count, never 'not proven'.
*   **P1.8.h** Numbers still being checked (client-side scan of GET /numbers): Chips read 'Checking numbers', never 'none'.

## Goal (KPI)
**65 in 100 agents that answer a production session get a 2-turn outside caller by day 14.**
*   Metric: Proven after production answer
*   Target: ≥ 65 % by day 14 of create (inbound, code)
*   How we measure: agent_answered_production to agent_proven, both within 14 d of agent_created, share of agents with agent_answered_production; batch excluded until turn count ships (G2). Interim until G2: production sessions over the stage 10 threshold on 2 distinct days, provisional.
*   Counter-metric: Stalled deployments ≤ 20 %; production sessions under 45 s ≤ 15 % (both need G2)
*   Assumption: Showing the missing step moves agents to a proven session. Method: cohort read; kill below 45 %.
