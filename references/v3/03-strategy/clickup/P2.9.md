## Job to be done (Sam, a developer)
**Job:** See what the agent was doing · job map stage **Locate** (Sam finds the inputs, the session or the cause)
**Umbrella job (P2):** Sam wants to find out what happened in a session, or in a set of sessions, and why.
**Situation:** Sam sees what the agent was doing at the moment something went wrong.
**Sam wants to:** read what the agent recorded at the moment it failed
**So that:** Sam can go from that line to the fix and back

### P2.9.a Happy path (this is what Sam does)
1. The Logs tab lists lines with severity (derived), module, time from start and event type; Sam filters and searches.
2. Sam expands a line (?log=<key>): message, raw JSON and View in context.
3. Links lead to the error group, the setting (P1.6), the turn once the join is verified, and Copy link.
4. Status detail stays in the header, never as a log line.

### Rainy paths (each needs its own state in the prototype and a frame in Figma)
*   **P2.9.b** Logs not available: 'Logs arrive with session analytics'; Status detail stays in the header.
*   **P2.9.c** Content is not stored: Zero retention: says what is never stored.
*   **P2.9.d** A line has no module: 'module unknown', with no setting door.
*   **P2.9.e** Over 2,000 lines: Paged, with errors pinned.
*   **P2.9.f** An old link points to a line that is not there: 'This line is not in this session'; the session opens. 'Expired' only when retention has passed.
*   **P2.9.g** An info line: No error group link.
*   **P2.9.h** Error groups are approximate until real error codes ship: The group link is marked approximate.
*   **P2.9.i** The active filter hides the lines around the one Sam opened: View in context shows 5 lines either side anyway.
*   **P2.9.j** The error stream is down (G11): 'Errors unavailable', never 'No errors'.
*   **P2.9.k** A line carries a secret value: The value is masked in the line, the raw JSON and every download.

## Goal (KPI)
**In one line:** Half of error line opens lead to the error group, the turn or the setting.
*   Metric: Line to next step
*   Target: ≥ 50 % of error line opens
*   How we measure: log_line_opened {severity: error} followed by monitoring_pivot {fromLevel: log} to group, turn or setting in the same visit, share
*   Counter-metric: Lines left in < 5 s ≤ 30 %
*   Assumption we are testing: Linked lines cut time to fix; the average Sam opens two or three error lines per failed session. Compare v2 sessions against status-only ones; kill the links if the gap is under 20 %.
