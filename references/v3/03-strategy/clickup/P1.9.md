## Job to be done (Sam, a developer)
**Job:** Define a good session · job map: Define
**Situation:** Sam decides what a successful session looks like for the agent. First in the P1 job map, and cross-linked from P0.4.
**Sam wants to:** know how many people actually booked an appointment
**So that:** Sam defines that once on the agent instead of per number or run
**Part of P1 Monitoring · Agents:** Keep every agent working for people outside the team

### P1.9.a Happy path: what Sam does
1. In the builder, Sam opens the Analysis section.
2. Sam adds criteria (for example 'Appointment booked') and fields with their types and enums.
3. Sam saves; the definition applies to every deployment type.
4. The API reference is linked from a tooltip; the API name never appears as a UI word.
5. Once results ship, a result in session detail links back to its field here.

### Rainy paths: when it goes wrong
*   **P1.9.b** No fields yet: A set-up prompt, never zeros.
*   **P1.9.c** Old criteria live on runs or numbers: Import once into the agent.
*   **P1.9.d** A field is renamed: Past results keep the old name.
*   **P1.9.e** Results are deferred: 'Arrives with session analytics'.
*   **P1.9.f** Sam leaves with unsaved fields: Ask Save or Discard.
*   **P1.9.g** A field is invalid (duplicate name, empty enum): Inline error on the row; save blocked with the reason.
*   **P1.9.h** Save fails (PATCH /agents 400 or 429): Fields kept, error code shown, Retry.
*   **P1.9.i** Session content was never kept (zero retention): Result reads 'Not scored: zero retention', never failed.
