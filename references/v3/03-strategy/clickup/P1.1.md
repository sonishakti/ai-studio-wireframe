## Job to be done (Sam, a developer)
**Job:** Know whether an agent needs attention · job map: Monitor
**Situation:** Sam finds out whether an agent needs attention right now.
**Sam wants to:** know whether the support agent is fine this morning
**So that:** Sam can either move on or act at once
**Part of P1 Monitoring · Agents:** Keep every agent working for people outside the team

### P1.1.a Happy path: what Sam does
1. Sam opens the agent from Agents; the agent page opens on Overview with tabs Overview, Analytics, Logs and diagnostics, and Runs when the agent has at least one run.
2. The header reads name, deployment type, deployment status, sessions in range, '2 error groups · 3 warning groups' and the last change.
3. Running now shows what the agent is handling at this moment (built in P1.2).
4. '1 new since 14:02 change' tells Sam whether the last edit brought a new error.
5. Sam clicks the error count and lands on Logs and diagnostics with the same range and severity.
6. Doors stay in the header: Edit agent, Talk to agent (P1.2), Sessions and 'Sessions since this change'.

### Rainy paths: when it goes wrong
*   **P1.1.b** Errors cannot be read (stream not wired): Header reads 'Errors unavailable', never 0; the Logs door stays and says why it is empty.
*   **P1.1.c** Sessions are not linked to the agent yet (G4): Sessions count reads 'Not linked yet', never 0, with a door to all sessions.
*   **P1.1.d** No production session yet: Counts are hidden; deployment status leads and names the next missing step (P1.8).
*   **P1.1.e** Link opens a deleted agent or one Sam cannot access: Not-found state names the reason, with a link to Agents.
*   **P1.1.f** No warnings can be derived yet: Warning count is hidden, not shown as 0, until an event type carries a warning.
*   **P1.1.g** Agent changed through the API, so Studio has no change time: Header falls back to updated_at and labels it 'Last saved', not 'last change'.
*   **P1.1.h** History shows more sessions than the agent counts: A note says tests and ephemeral sessions are left out of agent numbers.
*   **P1.1.i** Counts load slowly: Each count shows a skeleton; name, status and doors work first.

## Goal (KPI)
**Half of agent page visits with an error end in the error group opened.**
*   Metric: Error badge follow-through
*   Target: ≥ 50 % of agent page visits with an open error group
*   How we measure: agent_page_opened {errorState: errors} to error_group_opened in the same visit (visitId, 30 min inactivity), share of those visits
*   Counter-metric: Badge opens that leave Logs in under 5 s ≤ 30 %
*   Assumption: A count in the header sends Sam to Logs and diagnostics more reliably than a colored state. Method: cohort read; kill below 30 % follow-through.
