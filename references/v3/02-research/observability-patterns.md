# Observability patterns for v3 session history and agent monitoring

Research into how observability, product-analytics, and LLM/agent-observability tools solve the exact problems named: metrics that recompute on filter, drill-down from aggregate to one call, agent↔run↔session backlinks with shareable deep links, and a top-level error/warning badge. Every claim is sourced from vendor docs or a real screen (Refero id + URL). Refero's index has no direct screenshots of Datadog, Honeycomb, Sentry, Grafana, or the LLM-ops tools (gated enterprise UIs it hasn't crawled) — those come from vendor docs. Refero did surface close analogues: filterable event tables, severity-badged log lists, session-replay lists, and a voice-AI session detail page (Hume AI) that already does much of what "session detail" needs.

## Query & filter model

Two mental models coexist in every tool, without forcing a choice. Datadog offers a **typed search bar** for people who think in queries and a **facet sidebar** of the same fields as clickable chips for people who don't ([search syntax](https://docs.datadoghq.com/logs/explorer/search_syntax/), [facets](https://docs.datadoghq.com/logs/explorer/facets/)). Grafana's Loki editor makes the two modes literally interchangeable — Builder and Code tabs stay synced so a user can start clicking and finish typing LogQL. Honeycomb adds a third mode for when neither a query nor a facet click is the right tool: **BubbleUp** lets you box-select a cluster on a chart (e.g. low-scoring calls) and it diffs that selection against the baseline across every dimension, surfacing what they share ([BubbleUp](https://www.honeycomb.io/platform/bubbleup)) — worth a later-stage "why are these different" affordance on Agora's score/latency histograms. For now: CX ops reviewing "angry calls" need the chip sidebar; engineers debugging an outage need the query bar. Build one filter state with two renderings, not two filter systems — a facet click and a typed term should write to the same query object.

## Time model

Every tool anchors the page to **one global time range** driving everything on it — Datadog's Log Explorer/RUM Explorer/Service page and Grafana Explore's time picker all share this. The team's own framing — "change 30 days to 3 months and both the sessions list and the metrics change" — is exactly this model: time range plus query gate both the chart and the list underneath. Compare-to-previous-period and drag-to-zoom on a chart are standard at Datadog and Grafana but weren't confirmed in the docs pulled here; treat as should-have, not must, for v3.0.

## Metrics-over-list

This is the team's central ask, and it's Amplitude/Mixpanel's whole premise: a Segmentation chart and a filtered event list are two views over the same query, so changing the filter changes both ([Segmentation](https://amplitude.com/docs/analytics/charts/build-charts-segmentation-module)). PostHog goes further operationally — because analytics, replay, and the event stream share one data model, clicking a funnel drop-off lands inside a replay of that exact session, no separate query. For Agora: an agent's Analytics-tab KPI tiles and the "view sessions" drill-through must read from the same filter/time state as the tile, so clicking a tile is never a re-query with different assumptions.

## Saved views & shareable URLs

Datadog Saved Views persist "a search query along with its time range and a selected subset of facets ... for centralized access by everyone in your organization" ([Saved Views](https://docs.datadoghq.com/logs/explorer/saved_views/)). PostHog's replay carries the same idea as reusable saved filters. Fingerprint's events table exposes a plain **Copy link** that encodes the current filter state in the URL ([e4ccb081](https://refero.design/pages/e4ccb081-2e70-4323-a8b3-a5aaeec4ede6)) — the minimum bar for the agent↔run↔session backlink requirement.

## Drill-down path

Sentry's three-depth model is the cleanest reference: **issues list** (grouped, sparkline, lifetime counts) → **event detail** (stack trace, tags, inline breadcrumbs) → **full breadcrumb drawer** ("View All" opens its own search/filter/sort) ([Issue Details](https://docs.sentry.io/product/issues/issue-details/)). Each depth adds detail without discarding where you came from. For Agora: agent (aggregate) → run/campaign (a batch) → session (one call) → turn (one exchange), with a breadcrumb trail up at every level and URL state precise enough to paste into Slack and land in the same place.

## Error/log presentation

Avoid a flat, ungrouped error stream. Datadog Error Tracking fingerprints on "the error type, the error message, and the frames that form the stack trace" so thousands of similar errors collapse into one Issue with first/last-seen and impacted-count ([Error Grouping](https://docs.datadoghq.com/error_tracking/error_grouping/)); Sentry's issue list is the UI expression of the same idea. Lovable's Logs tab shows the row-level pattern to copy: a compact colored severity pill (INFO blue, WARNING terracotta), truncated monospace message, chevron to expand ([1ace48ed](https://refero.design/pages/1ace48ed-8d44-41e0-8509-e3161eadbd9d)). The top-level "2 errors, 3 warnings" badge is exactly Datadog's Service-page health badge, rolling up monitors + incidents + Watchdog into Critical/Warning/Ok. For an empty state, say so plainly rather than showing a zeroed chart — none of the docs fetched specify copy, so default to Agora's own quiet-chrome, no-seeded-data guidance.

## Detail page anatomy

Langfuse's model is the direct analogue for a voice session: a **trace** is the parent (one call), **observations** are the steps (ASR, LLM turn, tool call, TTS) sharing a trace_id, and a **session** groups multiple traces (a campaign or multi-turn conversation) ([data model](https://langfuse.com/docs/observability/data-model)). Scores attach at trace/observation/session granularity with their own tab ([Scores](https://langfuse.com/docs/evaluation/evaluation-methods/scores-via-ui)). LangSmith's run tree makes each observation clickable, opening its input/output panel on the right without leaving the trace. Hume AI's chat detail is the closest real screen to a voice-session detail page: three columns — nav, a middle **Evaluation** card (horizontal score bars) plus **Chat details** (status, start/end, duration, ID), and a right **Transcript / Call summary** tab pane — with a persistent bottom audio player (play, scrubber, download) ([1ad5409a](https://refero.design/pages/1ad5409a-cea5-4b6f-88f0-320684d486dc)). Agora's session detail should combine these: a turn-by-turn timeline with latency legs (ASR→LLM→TTS, each timed), a transcript panel, a scores panel, a metadata panel, and — per Base44's Activity Monitor pattern ([d2675eb7](https://refero.design/pages/d2675eb7-be0a-43b6-8bc1-2e03e0029662)) — a raw-JSON toggle per turn for engineers.

## Zero-retention/redacted rows

No fetched vendor doc describes a "zero data retention" row pattern directly (this is more specific to voice/PII compliance than general observability). Closest precedent: Sentry can collapse a field from view without deleting it, and Datadog masks sensitive log attributes at the facet level. Recommendation: render a zero-retention session as a normal row (so volume/cost totals stay correct), but replace transcript/audio/turn detail on its detail page with an explicit "Zero data retention — only call metadata and cost were kept" state, never a silently empty transcript panel.

## Configurable columns

Fingerprint's Events table is the direct reference: a **Display** control toggles visible columns and switches compact/comfortable density, with sortable headers ([e4ccb081](https://refero.design/pages/e4ccb081-2e70-4323-a8b3-a5aaeec4ede6)). Session history should let a user choose from cost, duration, score, outcome, direction, modality, agent version, and campaign, persisted per saved view — so a CX lead's default columns differ from an engineer's without forking the product.

## Anti-patterns to avoid

- **Vanity dashboards** — every tile must be a metric someone acts on (error rate, cost, score), not a raw counter nobody queries against.
- **Metrics that don't move with the filter bar** — a KPI tile ignoring the active search/time state breaks trust in every number on the page.
- **A flat, ungrouped error stream** — raw log lines instead of grouped issues defeats the "6 calls failed, TTS credits ran out" example the team gave.
- **Aggregation living in session history** — the team was explicit that session history is drill-down only; duplicating charts there re-creates what Datadog avoids by separating Explorer (search) from Service page (aggregate).
- **Dead-end charts** — a chart point that isn't clickable into underlying rows breaks "scrub through time and content."
- **Un-shareable state** — filters/time range living only in component state, not the URL, blocks the agent↔run↔session backlink requirement.
- **Green ticks as validation** — per the team's quiet-chrome rule, status badges should read "you configured this," not "this passed" — the same logic should shape how the error/warning badge is worded (counts, not reassurance).
- **Hiding zero-retention sessions from totals** — excluding them to avoid an empty transcript understates real volume and cost.
