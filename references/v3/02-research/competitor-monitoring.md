# Competitor research: agent monitoring, session history, and post-call analysis

Scope: how Vapi, Retell AI, ElevenLabs Agents Platform, LiveKit (Agents + Cloud), Bland AI, Synthflow, and one voice-QA vendor (Cekura) handle agent-level monitoring, the call/session list, the call detail page, post-call analysis, error/log surfacing, batch-call monitoring, and zero-retention/privacy modes. Researched via vendor docs (WebFetch) and web search on 2026-09-24. Refero (real-screen search) returned nothing relevant — searches for "Vapi call logs dashboard" and "voice agent analytics dashboard call transcript detail" surfaced unrelated CRM tables, options-trading UIs, and voice-cloning tools (Hume, Cartesia, ElevenLabs' voice isolator), so this doc relies on docs/blog descriptions, not Refero screens.

**Why Cekura, not Hamming/Coval/Roark**: Hamming's tutorial docs (`docs.hamming.ai/guides/*`) are access-gated behind a code wall; Coval's docs are mostly blog-style pages without a public reference tree; Roark has a thinner public doc footprint. Cekura publishes an open docs site (`docs.cekura.ai`) plus a large public blog with concrete dashboard/terminology detail, so it gave the most citable material.

## 2. Per-vendor notes

### Vapi
Monitoring spans three surfaces: **Overview** (usage + assistant performance, redesigned in Dashboard 2.0) [[1]](https://vapi.ai/blog/vapi-dashboard-2-0), **Boards** (self-serve drag-and-drop dashboards, Math.js calculated metrics, global time filters) [[2]](https://docs.vapi.ai/observability/boards-quickstart), and **Monitors → Issues → Notifiers** — define a metric+threshold, breaches create an **Issue** with affected call IDs and AI root-cause analysis, and **Notifiers** push to Slack/email/webhook [[9]](https://docs.vapi.ai/observability/monitoring-quickstart). This is the most alerting-mature vendor reviewed.

Post-call analysis, **Call Analysis**, is moving from a legacy `analysisPlan` to reusable **Structured Outputs** — schema-defined extraction/scoring definitions attached to assistants via `artifactPlan.structuredOutputIds`, with a **Rubric** concept (NumericScale, Checklist, PassFail) for scoring [[11]](https://docs.vapi.ai/assistants/call-analysis) — decoupling "what to extract" from "which assistant uses it" so one definition is reusable across agents.

Errors surface through an `endedReason` taxonomy: billing/credit exhaustion, missing assistant/resource resolution, LLM/TTS/STT provider errors by HTTP-status pattern (`*-400`, `*-429`, `*-500`), and SIP codes (403/408/480/503) [[30]](https://docs.vapi.ai/calls/call-ended-reason). Recording/logging/transcription toggle independently per assistant or per-squad-member (useful for muting a payment hand-off mid-call) [[25]](https://docs.vapi.ai/assistants/call-recording). HIPAA mode stores in Vapi's private compliant storage by default or redirects to customer S3/GCS [[35]](https://docs.vapi.ai/security-and-privacy/data-flow), with no documented UI treatment for an unretained call.

### Retell AI
Retell's post-call analysis is the most schema-explicit reviewed: every call gets built-in `call_summary`, `user_sentiment`, `call_successful`, `in_voicemail`, plus user-defined **Custom Analysis** fields (Boolean / Text / Number / Selector) [[12]](https://docs.retellai.com/features/post-call-analysis-overview). Results surface identically via dashboard, `call_analyzed` webhook, and API — a clean pattern for keeping Agora's dashboard and API in sync.

The global Analytics dashboard covers success rate, transfer rate, call counts, latency variance, and **A/B comparison across agents/campaigns** [[3]](https://www.retellai.com/changelog/performance-analytics-cf-testing-and-more). Batch outbound is **Batch Call**: a Draft-then-send tab, CSV-driven dynamic variables (any extra column becomes a prompt variable), in-tab progress/history [[33]](https://docs.retellai.com/deploy/make-batch-call). Retention is configurable per agent, 1 day–2 years, with a 3-tier PII policy (store everything / exclude PII / basic attributes only); Retell also excludes personal identifiers from its own internal logs/analytics by default [[26]](https://docs.retellai.com/general/compliance) — more granular per-field PII control than most competitors document.

### ElevenLabs Agents Platform (Conversational AI)
ElevenLabs has the richest **filtering vocabulary** reviewed: conversation history supports full-text keyword search, semantic **Smart Search**, and filters on time, duration, rating, tools, language, tags, topics, tool success/error, visited-agent/branch, and evaluation/data-collection IDs [[18]](https://elevenlabs.io/docs/eleven-agents/customization/agent-analysis/smart-search) [[19]](https://elevenlabs.io/docs/api-reference/conversations/list) — the strongest reference for Agora's "filterable by time/content/scores" requirement.

Post-call analysis splits into two named sub-features: **Success evaluation** (up to 30 custom criteria/agent, mostly goal-prompt LLM judges returning Success/Failure/**Unknown** + rationale — the Unknown bucket is a useful signal Agora's spec doesn't yet have a slot for) [[13]](https://elevenlabs.io/docs/eleven-agents/customization/agent-analysis/success-evaluation), and **Data collection** (structured field extraction) [[14]](https://elevenlabs.io/docs/eleven-agents/customization/agent-analysis). Both are filterable dashboard dimensions, not just detail-page content — worth matching in Agora's design.

Retention is agent-configurable per data type (transcripts vs. audio independently), default 2 years, 0 = immediate delete, -1 = unlimited [[27]](https://elevenlabs.io/docs/eleven-agents/customization/privacy/retention). **Zero Retention Mode** (Enterprise) deletes most request/response data immediately and is required (with a signed BAA) before sending PHI — but it explicitly **cannot be combined with batch calling** [[36]](https://elevenlabs.io/docs/eleven-api/resources/zero-retention-mode), a concrete precedent that zero-retention and batch/outbound genuinely conflict.

### LiveKit (Agents framework + Cloud "Agent Insights")
LiveKit is infra, not an agent-authoring product, so its monitoring is closer to raw observability than curated analytics. **Agent Insights**, inside the Cloud project's Sessions dashboard, shows one synchronized timeline per session: turn-by-turn transcript (tool calls/handoffs inline), trace spans (token counts, durations), runtime logs, playable/downloadable audio [[5]](https://docs.livekit.io/deploy/observability/insights/) — precedent for a single merged detail view over separate tabs.

Two privacy details stand out: a **hard 30-day retention ceiling on every plan** with auto-deletion after, stricter than any other vendor reviewed [[5]](https://docs.livekit.io/deploy/observability/insights/); and **PII redaction before storage** (not after), bundled free, off by default — a meaningfully different mechanism than "don't store it." LiveKit also supports scoped, time-bound **sharing a session's insight with LiveKit support** (Ship plan+) without extending retention [[5]](https://docs.livekit.io/deploy/observability/insights/). Recording granularity (`record` param for audio/transcript/traces/logs independently) mirrors Vapi's per-assistant approach [[5]](https://docs.livekit.io/deploy/observability/insights/).

### Bland AI
Bland's dashboard is lean in public docs: call logs, credit usage, agent configs, webhooks; Enterprise unlocks latency, sentiment, silence count, transcription quality, engagement, interruptions [[6]](https://app.bland.ai/dashboard/analytics). The standout is **Batch Calls**: CSV recipients (strict no-space column names, since columns become `{{variable}}` tokens), a five-state lifecycle (Initializing → Validating → Dispatching → In Progress [+chunked] → terminal), and dual monitoring — **status webhooks** per lifecycle transition, or the **Batch Calls dashboard** (status/name/timestamp/ID per batch, linking into batch-filtered Call Logs) [[20]](https://docs.bland.ai/tutorials/batch-calls). **"Completed Partial"** as a terminal status is a useful naming precedent for a multi-recipient batch. Invalid/blank numbers are auto-skipped and reported to error logs [[20]](https://docs.bland.ai/tutorials/batch-calls).

On privacy, Bland documents configurable per-data-class retention, on-demand deletion **with proof of completion**, isolated (non-pooled) tenant audio, and a 60-day HIPAA breach-notification SLA [[38]](https://www.bland.ai/trust-security) — "proof of completion" on deletion is a specific commitment other vendors don't make explicit.

### Synthflow
Synthflow's **Logs** page has the most tab-structured call detail reviewed: **Overview** (status, timestamps, agent, contact, labels — distinguishing total duration incl. PBX/ring time from recording duration), **Transcript** (speaker-labeled, inline action/KB markers), **Actions** (steps with duration/status, expandable req/resp), **Telephony** (a literal SIP call-ladder diagram) [[24]](https://docs.synthflow.ai/logs) — the SIP ladder is a concrete telephony-debugging affordance Agora doesn't yet have an equivalent for.

Its Analytics Dashboard blends global and per-agent views in one screen (an "assistant performance" card ranks agents by minutes/calls/success-rate inside the workspace-wide dashboard) [[10]](https://docs.synthflow.ai/collect-analytics), and surfaces **"reasons behind ended calls"** plus a dedicated **failed-calls table** (contact, date, duration, agent) as first-class cards, not buried in a log [[10]](https://docs.synthflow.ai/collect-analytics) — a good precedent for a "2 errors, 3 warnings" badge that links to a pre-filtered failed-session view. Export is API-only, capped at 120-day ranges [[7]](https://docs.synthflow.ai/collect-analytics). Retention is tier-based with a per-agent opt-out of saving recordings/transcripts under "Security & Compliance" [[21]](https://docs.synthflow.ai/logs).

### Cekura (voice-QA layer, sits on top of the above)
Cekura is a third-party evaluation/observability layer plugging into Retell, Vapi, ElevenLabs, LiveKit, Pipecat, Bland, Cisco, and Five9 [[39]](https://www.cekura.ai/blogs/custom-kpis-voice-agent-monitoring) — a picture of what a sophisticated third party bolts onto vendor consoles when native tooling falls short. Vocabulary: **scenarios** (test cases, incl. auto-generated and adversarial/compliance ones), **test runs** (scenario batches with pass/fail rates), **metrics** (30+ built-in across speech quality, conversational flow, accuracy/reasoning, plus custom KPIs mapped to business outcomes) [[15]](https://www.cekura.ai/blogs/custom-kpis-voice-agent-monitoring), and an **Observe** dashboard family (custom dashboards, metric plots, group-by filters, trend alerts) [[8]](https://www.cekura.ai/blogs/cekura-dashboards-the-qa-command-center-for-chat-and-voice-agents).

Most transferable idea: **every production call is auto-scored against the same metric set used pre-release, and each metric is simultaneously a Runs-table column, a trend line, and a drill-down filter** — one definition, three consumption surfaces [[8]](https://www.cekura.ai/blogs/cekura-dashboards-the-qa-command-center-for-chat-and-voice-agents), a stronger integration between analysis field and list/filter than any first-party vendor documents. Cekura also uses **adaptive baselines** — alerts fire only when a metric moves from an agent's own historical pattern, not a fixed threshold [[31]](https://www.cekura.ai/blogs/custom-kpis-voice-agent-monitoring), a more mature model than Vapi's static-threshold monitors.

## 3. What nobody does well (open squares for Agora)

- **No vendor unifies "call history" and "session history" across modalities.** Every call/session list reviewed is phone- or WebRTC-centric first; WhatsApp, code-initiated, and RTC sessions never live in one filterable list. Agora's modality-aware (RTC/telephony/WhatsApp) and direction-aware (inbound/outbound/code) unified Session History has no documented precedent here.
- **No vendor documents a UI treatment for zero-retention sessions.** Vapi, ElevenLabs, and LiveKit document retention *mechanics* (HIPAA storage, Zero Retention Mode, redaction-before-write) but none describes what the call list/detail actually *renders* when content was never stored — Agora's "shows only that the call happened and its cost" is more UI-explicit than any competitor's public docs.
- **Ephemeral / inline-agent sessions have no documented equivalent.** Every session in every vendor's model belongs to a saved agent/assistant ID; a session with no persistent agent to link back to appears to be a genuinely novel UI state.
- **Zero-retention and batch/outbound are in real tension, and only ElevenLabs says so out loud** — ZRM explicitly can't combine with batch calling [[36]](https://elevenlabs.io/docs/eleven-api/resources/zero-retention-mode). No vendor shows a *campaign → run → session* hierarchy with mixed retention modes within one run.
- **Alerting maturity is uneven and mostly outsourced.** Only Vapi (Monitors/Issues/Notifiers) and Cekura (adaptive-baseline alerts) document real threshold/anomaly alerting; Retell, ElevenLabs, Bland, and Synthflow surface errors passively. Agora's "2 errors, 3 warnings" badge is closer to a merged Vapi+Cekura experience than any single vendor ships today.
- **Custom analysis fields rarely become list/filter facets.** Retell's Custom Analysis and Vapi's Structured Outputs are detail-page content only; ElevenLabs and Cekura are the exceptions, treating analysis fields as list/filter dimensions too — an opportunity for Agora's "analysis" block to do this by default.
- **No vendor documents a batch/campaign hierarchy as deep as Agora's campaign → run → session.** Vapi's "Campaigns," Retell/Bland/ElevenLabs' "Batch Call"/"job" are all one flat list of calls; none has an intermediate "run" grouping repeated executions of the same campaign.
- **Share links are rare.** Only LiveKit documents a scoped share (to its own support, not teammates), and only Vapi documents direct call-ID deep links. A general "share this session with a colleague" pattern isn't solved anywhere reviewed.

## 4. Naming across the market

| Concept | Vapi | Retell AI | ElevenLabs | LiveKit | Bland AI | Synthflow | Cekura |
|---|---|---|---|---|---|---|---|
| **Post-call analysis** | Call Analysis (Summary / Structured Data / Success Evaluation) | Post-Call Analysis (built-ins + Custom Analysis) | Conversation analysis → Success evaluation + Data collection | N/A (raw traces/metrics only) | Not named as a distinct feature | Not named as a distinct feature (sentiment + end-reason) | Evaluation (pre-release) / Metrics (production) |
| **Structured extraction** | Structured Outputs (+ Rubrics for scoring) | Custom Analysis fields (Boolean/Text/Number/Selector) | Data collection | N/A | N/A (documented) | N/A (documented) | Custom metrics / custom KPIs |
| **Batch/campaign** | Campaign | Batch Call | Batch calling | N/A | Batch Call | Not a distinct product | N/A (consumes from source) |
| **Run/execution of a batch** | Not distinctly named | Individual "calls" within a Batch Call | "Job" (create/list/get/retry/cancel) | N/A | Individual calls within a batch, tracked by lifecycle "status" | N/A | Test run (pre-release), scored calls (production) |
| **Session/call/conversation** | "Call" | "Call" | "Conversation" | "Session" | "Call" | "Call" (also "chat" for non-voice) | "Call" (inherits source vendor's term) |
| **Zero/limited retention** | HIPAA mode (private compliant storage) | Configurable retention (1 day–2 yrs) + PII tiers | Zero Retention Mode (Enterprise) | 30-day hard ceiling + PII redaction | Configurable per-data-class retention | Per-agent opt-out of saving recordings/transcripts | N/A |

Two patterns worth noting for Agora: **(1)** ElevenLabs and Vapi both independently converged on "success evaluation" for goal-completion scoring — closer to plain language than Retell's generic `call_successful` boolean. **(2)** Every phone-first vendor (Vapi, Retell, Bland) calls the unit of work a "call," while LiveKit — infra-first, modality-agnostic — calls it a "session." Since Agora's v3 spec is explicitly modality-aware and not phone-first, "session" is the more defensible umbrella term, reserving "call" for telephony-modality sessions specifically.
