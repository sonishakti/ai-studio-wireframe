# Builder research: model/voice presets, deployment-first creation, secrets UX

Date: 2026-09-24. Scope: informs the v3 agent builder simplification (Voice & model → 3-4 line preset radio + one Advanced panel; deployment type chosen at creation; Credentials → Secrets with named secret sets). Every claim below is cited to a vendor doc, changelog, or a Refero screen id. Refero access worked for all four queries; results are noted inline.

---

## A. Model/voice/transcriber selection UX

| Vendor | Pattern | Source |
|---|---|---|
| Vapi | Three tabs map straight to the pipeline: **Model**, **Transcriber**, **Voice** (Think/Listen/Speak). Each has a provider dropdown (OpenAI, Anthropic, Google, Deepgram, ElevenLabs, PlayHT, etc.). New assistants default to a **"Balanced" preset** bundling transcriber+model+voice so a non-expert ships without touching any tab. | [docs.vapi.ai/quickstart](https://docs.vapi.ai/quickstart), [docs.vapi.ai/assistants/quickstart](https://docs.vapi.ai/assistants/quickstart) |
| Retell | `response_engine` is a top-level **type**: Retell LLM (`llm_id`), Custom LLM (WebSocket), or Conversation Flow. `voice_id` is required; the **provider** enum (ElevenLabs, Cartesia "Sonic", OpenAI, Minimax, Inworld) is discoverable with preview only in the dashboard, not the API docs. Advanced voice params (`voice_temperature`, `voice_speed`, `voice_emotion`, `expressive_emotion_tags`) sit beside the basics, not tab-separated. | [docs.retellai.com/api-references/create-agent](https://docs.retellai.com/api-references/create-agent) |
| ElevenLabs Agents | LLM is one dropdown across four providers (ElevenLabs Qwen, Google Gemini, OpenAI GPT, Anthropic Claude). Docs coach the choice on four axes — complexity, latency, context window, cost — rather than a fixed pick. **Custom LLM**: point at your own endpoint, credentials via the workspace Secrets store. TTS is an explicit quality/latency fork: `eleven_v3` (max expressiveness) vs `eleven_flash_v2_5` (~75 ms). Target given: time-to-first-audio under ~700 ms. | [elevenlabs.io/docs/eleven-agents/customization/llm](https://elevenlabs.io/docs/eleven-agents/customization/llm), [elevenlabs.io/docs/eleven-api/concepts/latency](https://elevenlabs.io/docs/eleven-api/concepts/latency), [elevenlabs.io/blog/…latency](https://elevenlabs.io/blog/enhancing-conversational-ai-latency-with-efficient-tts-pipelines) |
| LiveKit Agents | No visual picker: `AgentSession(stt=…, llm=…, tts=…)` set in code, any plugin swappable per argument. A hosted **Agents Playground** tests a running pipeline without a frontend, but selection itself is code-time, not dashboard. | [docs.livekit.io/agents/models](https://docs.livekit.io/agents/models/), [livekit.com/blog/…pipelines-explained](https://livekit.com/blog/voice-agent-architecture-stt-llm-tts-pipelines-explained) |
| OpenAI Agent Builder | Visual canvas (templates, drag-drop nodes, typed I/O, live preview). Model set per node or as a workflow default; guidance is simply "start flagship, downgrade only when latency/cost justifies it" — a default-then-downgrade heuristic, not a preset gallery. | [developers.openai.com/.../agent-builder](https://developers.openai.com/api/docs/guides/agent-builder), [.../agents/models](https://developers.openai.com/api/docs/guides/agents/models) |
| Bland | Model/voice config is secondary to the **pathway** (conversation graph) or task-based definition; the flow is the centerpiece, not a model picker. No logo-driven provider gallery found in public docs. | [docs.bland.ai](https://docs.bland.ai/welcome-to-bland), [bland.ai/blog/...setup-guide](https://www.bland.ai/blog/ai-phone-calling-setup-guide) |
| Synthflow | Model/voice/behavior/knowledge/deployment all live in one **Agent Editor**; users separately pick Prompt Builder (single prompt) vs Flow Designer (branching) for conversation logic. | [docs.synthflow.ai/the-agent-editor](https://docs.synthflow.ai/the-agent-editor) |
| Hume (EVI) | Voice from a **Voice Library** of 100+ presets plus clone/custom. Distinctive pattern: Hume's empathic LLM (eLLM) always answers first (fast); an optional **supplementary LLM** (OpenAI/Anthropic/Google/Fireworks, BYO) takes over mid-response for smarter, longer answers — latency-vs-intelligence solved structurally, not by a single toggle. | [dev.hume.ai/.../configuration/voice](https://dev.hume.ai/docs/speech-to-speech-evi/configuration/voice), [hume.ai/blog/...evi-3-api](https://www.hume.ai/blog/announcing-evi-3-api) |

**Refero:** "model selector with provider logos" returned **Raycast AI** composers with an inline model-dropdown chip (screens `1dea5e4e…`, `d3118a5e…`) and **Cursor's** composer with a compact model dropdown plus "multi-model mode" toggle (`2397b160…`). "AI voice picker with preview playback" returned **ChatGPT's** voice screen: a 3-up carousel (Sol/Arbor/Vale) navigated by arrows around one live avatar, Cancel/confirm actions (`3c237d7b…`, `926fdfeb…`) — a bounded 3-up list, not a long menu. No screen in either search showed a voice-AI vendor-logo grid; Vapi/Retell dashboards aren't in Refero's index (see Open Questions).

### Why users like it
Vapi's three-tab layout mirrors the actual signal path (listen → think → speak), teaching the architecture for free. Its **Balanced default** removes the anxiety of not knowing what to pick — exactly what Agora's "Lowest latency" default should do. ElevenLabs' four-axis coaching (complexity/latency/context/cost) turns "pick a model" into "pick a trade-off," the same framing the team wants for Agora's copy (latency vs intelligence, since price is now flat). Hume's fast-then-smart dual-LLM pattern is the closest analog to Agora's SuperNode positioning: it shows the trade-off can be designed away, not just chosen — worth flagging as a future preset idea. ChatGPT's 3-up carousel bounds decision fatigue by showing exactly 3 voices at once even though more exist.

### Translation for Agora v3
- Preset radio cards (**Lowest latency / Balanced / Custom**) each show a compact ASR→LLM→TTS logo-chip strip under the label, Vapi-tab-style, so a preset visibly shows what it's made of.
- Keep pipeline order (Listen → Think → Speak) consistent between the logo chips and the Custom panel's section order, so switching to Custom doesn't reshuffle anything.
- Write preset copy on latency and intelligence only, never cost (flat pricing): e.g. "Lowest latency: fastest reply, good for most calls" / "Balanced: smarter answers, a beat slower."
- Voice dropdown: borrow ChatGPT's carousel-preview idea for its expanded state — a short list (5-8 voices, not 10,000) with inline play, bounded like Retell's `voice_id` + preview.
- The single **Advanced panel** should use ElevenLabs' section grouping as a completeness checklist: LLM/ASR/TTS params, turn detection & silence, filler words, max history, MCP & tools, failure message — labeled sections in one scrollable panel (accordion sub-sections), not further tabs.
- Custom should open pre-filled with the Lowest-latency preset's real values (Deepgram Nova 3 / Gemma 4 on SuperNode / Cartesia Sonic 3.5), Vapi-style, so it's a starting point, not a reset.

## B. Agent creation flows that pick deployment/use type first

| Vendor | Pattern | Source |
|---|---|---|
| Synthflow | Two-step gate: (1) **Voice Agent** vs **Chat Agent**; (2) for Voice, **Inbound / Outbound / Voice Widget**. Only then does the user pick Prompt Builder vs Flow Designer, then configure voice/knowledge/deployment in one Agent Editor. Chat Agent's channel choice (widget/API/WhatsApp/SMS) is deferred to a later "launch" step — deployment-first applies specifically to voice. | [docs.synthflow.ai/create-an-agent](https://docs.synthflow.ai/create-an-agent), [docs.synthflow.ai/the-agent-editor](https://docs.synthflow.ai/the-agent-editor) |
| Retell | Type is chosen at the **response_engine** level (Retell LLM / Custom LLM / Conversation Flow) — a reasoning-engine choice, not a channel one. Inbound vs outbound is a property of which number is later attached, not of creation itself. | [docs.retellai.com/api-references/create-agent](https://docs.retellai.com/api-references/create-agent) |
| Bland | Ships a **Persona** abstraction so one agent identity reuses across many numbers. Inbound = purchase a number, attach it to a pathway/persona. Outbound = trigger calls via API/webhook. Pathway-vs-task choice is made at creation; inbound/outbound is numbers wiring done afterward, closer to Retell's model than Synthflow's. | [docs.bland.ai](https://docs.bland.ai/welcome-to-bland), [university.bland.ai/modules/2/lesson-4](https://university.bland.ai/modules/2/lesson-4) |
| Vapi | Assistants start blank or from a template; no dedicated "deployment type" gate — a number, web SDK, or SIP trunk is attached after the assistant exists. Weakest match to Agora's target pattern; useful as a deployment-type-last contrast case. | [docs.vapi.ai/assistants/quickstart](https://docs.vapi.ai/assistants/quickstart) |
| ElevenLabs | No explicit "pick inbound/outbound/web at creation" step surfaced in docs; agents configure after creation from a template — a documentation gap, not a confirmed pattern. | [elevenlabs.io/docs/eleven-agents/overview](https://elevenlabs.io/docs/eleven-agents/overview) |

### Why users like it
Synthflow's two-gate flow prunes the config tree before the user sees it — an inbound agent never needs "who are we calling" fields, an outbound batch agent never needs "ring timeout" — the first choice removes a category of settings instead of hiding them behind conditional visibility. Bland/Retell's identity-vs-number split is copyable too: the agent's *brain* and its *phone wiring* are different lifecycles, reusable/swappable independently, which maps directly onto Agora's model where deployment lives on Number/Campaign/Session, not the agent.

### Translation for Agora v3
- Creation dialog, Synthflow-shaped: one gate, three cards — **Inbound**, **Outbound batch**, **Code/SDK** — decided before the builder opens, each routing to a skeleton with only relevant sections visible (outbound batch never shows "ring behavior"; inbound never shows "contact list").
- Model after Retell/Bland's identity-vs-number split, which already matches the v3 API contract (deployment on Number/Campaign/Session): the creation-time choice sets which skeleton and rail items exist, but doesn't attach a number — that stays a Deployment-tab action, consistent with the section-rail builder shipped 2026-09-24.
- Use Vapi's deployment-type-last flow as the "why not" reference: faster to start, but every assistant's Model/Voice/Transcriber tabs then carry channel-irrelevant fields (e.g., voicemail detection shown even for a code-SDK agent).

## C. Secrets UX (naming, write-only display, rotation, scoping, inline creation)

| Vendor | Pattern | Source |
|---|---|---|
| Vercel | Env vars now have a **Config** or **Secret** type (replacing the old "Sensitive" toggle). Secret values are write-only after save: unreadable via API or dashboard, replaceable but not viewable, **key immutable** once saved, and not convertible to Config in place (delete + recreate). Rotation = re-enter a new value on the same key. Secret vars scope only to **Production/Preview**, not Development. Build logs auto-redact values ≥32 chars as `[REDACTED]`. Owners can force all new Prod/Preview vars to be Secret type org-wide. | [vercel.com/.../sensitive-environment-variables](https://vercel.com/docs/environment-variables/sensitive-environment-variables), [vercel.com/changelog/...config-and-secret-types](https://vercel.com/changelog/environment-variables-now-use-config-and-secret-types) |
| GitHub Actions | Secrets scoped at **org / repo / environment** level; environment secrets require a job to reference that environment, which doubles as an approval gate for protected environments like production. Precedence: environment > repo > org. Client-side Libsodium sealed-box encryption; workflow logs auto-redact secret values. Limits: 1,000 org / 100 repo / 100 env secrets, 48 KB each. | [docs.github.com/.../secrets](https://docs.github.com/en/actions/concepts/security/secrets), [docs.github.com/.../using-secrets](https://docs.github.com/actions/security-guides/using-secrets-in-github-actions) |
| Doppler | **Project → Environment → Config** hierarchy; each environment (dev/staging/prod) holds its own configs, plus a personal/private dev config per developer. **Branch configs** inherit an environment's values with overrides, for feature work without duplicating the set. **Service tokens** scope to project/environment/config, expire, read-only or read-write. Live dashboard (screens `b697943c…`, `736b65e4…`): left project sidebar, breadcrumb, filterable secrets list with per-row reveal/mask, and a **compare view** (`c5e712d0…`) diffing masked values across two environments side by side. | [docs.doppler.com](https://docs.doppler.com/docs/getting-started), Refero `b697943c-2142-4573-b4e8-2a345981c559`, `736b65e4-c842-439a-81ee-f849bbbffef0`, `c5e712d0-9b5f-4500-b1d8-84c586aa779e` |
| Infisical | Same environment/path scoping idea, via a web dashboard plus CLI/SDKs/K8s agents; one logical key holds different values per environment, similar in spirit to Doppler. | [infisical.com/.../secrets-mgmt/overview](https://infisical.com/docs/documentation/platform/secrets-mgmt/overview) |
| ElevenLabs (workspace secrets) | A dedicated Secrets API (get/create/update/delete/list) backs a **Workspace Secrets** store; secrets are **never revealed to the agent**, only inside a tool's server-side Context object. Tool auth layers on top: HTTP Basic via "Workspace Auth Connections," or a **Secret-type header** injecting a bearer token by referencing the secret's name, or custom headers. Webhook config (which can consume secrets) is admin-only. Closest existing pattern to Agora's `$secrets.<set>.<key>` reference-by-name model — the tool never holds the value, only a resolvable name. | [elevenlabs.io/.../secrets/create](https://elevenlabs.io/docs/api-reference/workspace/secrets/create), [elevenlabs.io/.../webhook-tools](https://elevenlabs.io/docs/eleven-agents/customization/tools/webhook-tools) |
| Vapi | Two tiers: **API keys** (public client-side / private server-side, auth to Vapi itself) vs **Provider Keys** (BYO vendor keys, added under the dashboard's Integrations tab). Once a provider key validates, Vapi stops billing for that provider and the vendor bills directly — pasting a key changes the pricing model, not just auth. A **CustomCredential** system adds OAuth2, HMAC, Bearer for arbitrary tool integrations. Guidance: never put a private key in client code, logs, screenshots, or agent chat. | [docs.vapi.ai/.../api-keys](https://docs.vapi.ai/security-and-privacy/api-keys), [docs.vapi.ai/.../provider-keys](https://docs.vapi.ai/customization/provider-keys) |
| Retell | Only a single-tier bearer API key to Retell itself is documented. For **Custom LLM** setups, Retell's own demo repos push the BYO-LLM key into a local `.env` outside the product — no documented first-party "secret set" UI for vendor keys, a real gap versus Vapi/ElevenLabs worth naming to the team. | [docs.retellai.com/api-references/overview](https://docs.retellai.com/api-references/overview), [github.com/RetellAI/retell-custom-llm-node-demo](https://github.com/RetellAI/retell-custom-llm-node-demo) |

**Refero screens:** "environment variables secrets settings page" surfaced close analogs beyond Doppler/Vercel. **Mocha** (`fd6a9488…`, `952f3edf…`, `ee0947c8…`) shows the simplest copyable pattern: a horizontal **key + value + Add** row above a masked secrets table, a persistent "deploy to take effect" reminder, inline edit/delete per row; its empty-state variant (`ee0947c8…`) confirms this pattern works with zero rows, matching Agora's "empty first" rule. **Rork** (`6b0a63ac…`, `a16ec0b3…`) shows a right-side-sheet editor for bulk-editing key/value pairs (reveal/add/delete/bulk-edit) — a pattern for editing a set without leaving the builder. **Equals** (`5b12f7bb…`) is the one screen naming the exact concept Agora wants — "secret groups for environment variables" — as an empty state with a single "create a new group" CTA: sets are first-class, creatable objects, not tags on individual keys.

### Why users like it
The common thread: **write-only-by-default is a trust signal, not just a control** — a value that can never be re-displayed can't leak retroactively via screen-share or a compromised account, which Vercel's docs frame explicitly ("non-readable once created"). Environment scoping (Doppler's Project→Environment→Config, GitHub's env-secret + reviewer gate, Vercel's Prod/Preview-only Secret type) matches how one logical key needs different values per stage without forcing users to invent `PROD_API_KEY` / `TEST_API_KEY` naming — environment is a dimension, not part of the name. ElevenLabs/Vapi's "reference by name, resolve server-side" model decouples *where a credential is used* from *where it's managed*: configure the use once and the value once, never re-typed together.

### Translation for Agora v3
- Make **secret sets** first-class named objects like Equals' "secret groups," not a flat key list — a set (`prod`, `test`) holds many pairs, matching `$secrets.<set>.<key>` addressing directly.
- **Auto-create on paste**: recognize a raw-looking key/token pasted into any provider field, prompt "Save this to a secret set?" defaulting to the agent's current environment, and replace the field's value with the `$secrets.<set>.<key>` reference — Mocha's add-row pattern (key + value + Add) triggered inline from the field itself.
- **Write-only display**: always render a masked placeholder after save (matching ElevenLabs' "never revealed" stance), with an "Edit" action that only accepts a new value — never "reveal" — following Vercel's Secret type (key immutable, rotate = overwrite).
- **Environments as a dimension of the set**, not the key name: a set duplicates across environments the way Doppler's branch configs inherit-then-override, so `$secrets.prod.stripe_key` / `$secrets.test.stripe_key` swap by changing which set the agent points at.
- **Delete protection**: show a "used by" list of agents/tools before deleting a set or key — none of the six vendors show this today (see Open Questions), so it's a genuine differentiator, built on the same reference-by-name plumbing ElevenLabs already uses.
- Borrow Doppler's **reveal/mask toggle for Config-type only, never Secret-type**, and its masked compare-across-environments view as a later nice-to-have for auditing prod/test parity.

## Open questions

1. **"Used by" / reference tracking is absent everywhere researched.** Vercel, GitHub, Doppler, Infisical, ElevenLabs, and Vapi all show a flat or environment-scoped secret list, with no documented delete-time warning listing which workflows/tools/agents reference a secret. Agora's delete-protection has no vendor pattern to copy wholesale — only ElevenLabs' name-based resolution to build on top of.
2. **No vendor shows quantitative latency/quality numbers inline in a model picker.** ElevenLabs' ~75 ms and <700 ms TTFA figures live in blog/concept docs, not the selection UI. Agora's preset copy should originate honest SuperNode benchmark numbers rather than echo a competitor's figure, to avoid overclaiming.
3. **LiveKit and Bland have no logo-driven model/voice picker** (code-first and pathway-first respectively) — the "delightful, logo-forward" reasoning really has three strong exemplars (Vapi, ElevenLabs, Hume) plus one undocumented one (Retell). A follow-up logged-in walkthrough (per the Secondary Research rule: 4 vendors minimum, docs + logged-in product screenshots) is needed to see Retell's and Vapi's actual dashboard pixels, since this pass only confirmed patterns from API docs.
4. **Whether a deployment type chosen at creation can be changed later** was not confirmed for any vendor. Synthflow implies the choice is structural, but no doc states whether switching after creation is possible or requires a new agent — relevant to how reversible Agora's own creation-time gate should be.
5. **Refero's index doesn't currently include Vapi, Retell, Synthflow, Bland, or Hume dashboards** — all Refero evidence above comes from adjacent AI-tool products (Raycast, Cursor, ChatGPT, Doppler, Mocha, Rork, Equals). All four searches returned results (no failures), but a dedicated screenshot pass of the named vendors is still needed before finalizing visual specs.
