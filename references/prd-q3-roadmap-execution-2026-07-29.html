1Problem statement

The Q3 roadmap defines what Engine, Studio, and SIP will ship — but almost none of it has a designed console surface. If the wireframe doesn't get ahead of it, each feature lands as an API-first afterthought bolted onto the UI, repeating the Console↔Studio seam failure the whole project exists to fix. Studio_X's job this quarter: design the console expression of every customer-facing roadmap item before engineering ships it, validated by simulated user tests, so the north star — signup → first live deployment carrying traffic → first paid usage — has a coherent surface at every step.

3Goals & non-goals

Goals

  • Every P0 roadmap item with a UI surface has a designed, user-tested console expression before its due month ends.
  • The builder's Test Strip becomes the quality loop's front door — simulations at scale, scoring, and human join-in are one continuous surface.
  • Observability closes the loop: any session failure is diagnosable (payloads, latency waterfall, SIP ladder) and routes to a fix.
  • Commerce is self-serve: numbers, concurrency, and capacity SKUs are purchasable in-console without a sales call.

Non-goals

  • Internal tooling — operator console for key rotation, telco ops dashboard (ASR/NER/PDD), SIP tracing internal tool. Different audience.
  • Backend-only work — /join API changes, traffic replay regression, Tier-3 Supernode, provider contract normalization (UI consumes, doesn't design).
  • Docs site work — AI doc assistant, deprecated-field cleanup live in docs.agora.io, not the console.
  • Physical AI builder — P2 scoping task only; parking lot.
  • Any real backend — Studio_X stays mock-data, per project charter.

5Execution waves — phased by the roadmap's own due months

Each wave is 1–2 graph-loop cycles on studio_x_2: build the slice → deploy → 3-persona user test → triage → fix → gate. P0s anchor each wave; P1s fill remaining capacity.

Wave 1 — now → mid-Aug July P0s (already due)

  • Templates + model selection (P0 2026-07) — template gallery, per-use-case model defaults
  • Latency waterfall in session detail (P0 2026-07, Engine already delivered the data)
  • Session details beyond telephony (P1 2026-07) + per-turn STT/LLM/TTS payload inspector
  • Couchbase RAG connector UI (P1 2026-07, explicit UI task)

Wave 2 — Aug 5 P0s due 2026-08

  • Managed mode — managed-vs-BYO provider credentials (P0)
  • Provisioning delay removal — first-run flow without the wait wall (P0)
  • SIP errors + CPS-limit failures surfaced in needs-attention + call detail (P0)
  • SIP ladder diagrams in call detail (P0)
  • Capacity SKU cards in Billing › Plans + SIP-DC meter (P0)
  • Simulations at scale + scoring report card (P1) · Warm transfer config + call-summary display (P1) · WhatsApp voice channel surface (P0, no due month)

Wave 3 — Sep commerce P0s due 2026-09

  • Phone number purchase & assignment flow (P0) + self-serve CPS on number detail (P0)
  • Concurrency self-serve with capacity-aware safeguards (P1)
  • Conversation-feel controls: tool-based filler words, backchannels, background sound (P1) · STT dictionaries + TTS pronunciation editor (P1) · Voice cloning entry (P1) · Stable Studio API surface in /developer (P1)

Wave 4 — Oct quality loop closes

  • Auto-detected errors feed in Diagnostics (P1) · MLLM metering row in Usage (P1)
  • Live monitor — sentiment trends, active calls, overseer prototype (P1)
  • Production call scoring + recording-review suggestions (P1) · Recurring-failure fixer (P2) · Graph editor first cut (P1, if capacity)

7Open questions

  • Phone-number resell scope (PM/legal, blocking Wave 3): which countries, and does BYO SIP remain a parallel path? The purchase flow design needs the answer for its empty/unavailable states.
  • Managed-mode billing (PM/finance, blocking Wave 2): does reseller-mode usage bill through existing postpaid, or a new SKU? Determines what the credentials surface promises.
  • Subtask expansion (PM, non-blocking): five Studio parents hide 31 subtasks (Accelerate setup ×14, Integrations ×6, Quality loop ×4, Simulation ×4, Inbound MVP ×3) not expanded in this read. Expand in ClickUp and slot into waves — likely refines Epics A/B/G but shouldn't add new surfaces.
  • Composer vs graph editor (design, non-blocking): one surface with two views, or two entries? Decide before the Wave 4 graph-editor cut.
  • Live-monitoring privacy (legal, non-blocking): operator listen-in needs consent framing; pairs with the PII-redaction Engine item.
