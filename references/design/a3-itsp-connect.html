A3 — Easy ITSP onboarding: paste a key, we build the trunk

A Quick-connect path folded into “Add a phone number”: drop in a Twilio/Telnyx credential and Agora configures the SIP trunk — a ~1-minute flow that ends on a real test call, replacing the 5–9 manual steps every competitor still demands.

◆ Built 2026-07-09 · held for local review (not yet deployed) commit eada0d8 PRD: roadmap-features-prd §3 · A3

The problem, in the user's own words

Three consecutive user-test sessions surfaced the same top-severity moment. D1, the hustler: “‘Agora doesn’t sell numbers’? It’s 9pm and I don’t have a SIP trunk. That line is where my night dies.” Agora genuinely sells no numbers (telephony is BYO SIP), so the fix can’t be “sell one” — it has to make connecting the number the user already owns take a minute, not an evening. Only ElevenLabs auto-configures at all (1/5), and even that is narrow (webhook wiring). Retell demands 5 manual steps across two consoles; Vapi, 9.

Validate key→ Find numbers→ Create trunk + routing→ Attach number→ Verify with a real call

The honest state machine (research)

A key→trunk flow really passes through five stages, each with real failure modes — the design renders them honestly rather than faking a one-click success:

StageFails whenHonest recovery
Validate credentials401 bad SID/tokenName the fix; link Account › API keys; state “nothing else happened”
Enumerate numberszero numbers / outbound-only caller IDsCapability badges before selection; deep-link to buy AT the carrier
Create trunk + routingpartial creationName the failed object; retry only that stage
Associate numberon another trunk (silent overwrite!) · geo-block 32205Pre-overwrite confirm; per-error copy + carrier link
Verifyprovisioned but calls don’t connectEnd on a real test call, not a “saved” check; offer manual fallback

Security: Twilio itself recommends scoped API keys over the master Auth Token — so the UI prefers the scoped key and labels the token “less secure.” Stored credentials mask to the last 4, timestamp, and disconnect ≠ carrier-side revocation (said plainly).

Diverge → converge (4 variants)

1 · Mode-toggle sheet

Quick|Manual toggle in one sheet. Won failure-honesty (9.3) + fold-fit (8.7) — folds literally into the existing sheet.

2 · Guided three-step

Connect · Pick · Verify stepper. Clearest picker + live call timer; thinner wait narration.

3 · Paste-and-go

One decision, a live fact-log, auto-pick. Won the 9pm test (8.7) — the emotional winner.

4 · Provider-first honesty

Doors that name their price up front. Most transparent; slowest to start, auto-ran the test call.

Verdict: V1 wins — failure-honesty disqualifies over feel, and V1 leads both honesty (9.3) and fold-fit (8.7) while near-tying V3 on the 9pm test (8.3 vs 8.7). Shipped = V1’s mode-toggle chassis + V3’s streaming fact-log and auto-pick + V2’s named picker step and live call timer. The manual SIP form survives verbatim as the sibling tab; every existing entry point (Resources › Channels, phone-numbers, channel-hero, the wizard SIP hints) inherits the upgrade because they all already trigger the same sheet.

What was built

sip-quick-connect.tsx

  • ≤4 inputs; scoped API key preferred, Auth Token one disclosure-click away
  • Append-only timestamped fact-log — real work, never a bare spinner
  • Capability-badged picker (outbound-only rows disabled + explained)
  • Ends on a user-placed test call (ring → connected + live timer)
  • Masked stored credential + Disconnect (≠ carrier revocation); manual fallback always one tap away

Fold-in & honesty

  • Persistent Quick connect | Manual SIP toggle in the existing sheet
  • Sheet description leads with “bring a number you already own”; the “sells no numbers” truth is fine print, not a gate
  • 9 events; test_call_connected is the success line (not trunk_created)
  • Provider-parameterized copy: Twilio “SIP trunk” vs Telnyx “FQDN connection”
Deferred to a follow-up (honest scope): the six failure scenarios (bad creds, no numbers, on-other-trunk overwrite, geo-block, verify-fail) were fully designed & judged in the lab; the shipped component implements the happy path + the load-bearing honesty moments (user-placed call, manual fallback, masked credential). Wiring each failure state into the mock is a fast next pass — the pattern is proven.
