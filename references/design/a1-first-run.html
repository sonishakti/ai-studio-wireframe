A1 — First-run: the provisioning ceremony & the named default

The >30-second project-creation wait becomes a staged, honest arrival moment that ends on “Aria is live — say hello.” The default stack gets a name and a why. The stale checklist dies; its persistence survives as a lib.

● Shipped 2026-07-09 commit a1387f7 Live: /agents?provision=1 ↗ Error state: ?provision=stall ↗

The structural advantage this makes felt

Research across Retell, Vapi, Bland, and ElevenLabs found that no competitor gives a new account a live agent — every one walls the first session behind create-an-agent and a template picker. Studio_X provisions Aria live on signup. A1's job was never to add onboarding chrome; it was to make that advantage felt in the first 60 seconds and credible through named defaults. The deck's own complaints — project creation >30s, templates undersell, defaults trail Retell — are all first-impression failures.

Diverge → converge

V1 · Ceremony

Full-takeover staged arrival ending in the landing. Honest end-to-end; grafts with zero surgery on the locked wizard. Weakness: a 40s wall — fixed via break-the-wall skip.

V2 · Instant-feel

Landing paints immediately; the Aria card warms in place. Best first-60-seconds feel; lost on a fabricated pre-checked stage and structural fold costs.

V3 · Working session

Provisioning as a self-completing journey row (endowed 1/6). Warmest wait story — about the wrong hero; demoted the live agent for a checklist.

Verdict: V1 wins both gating lenses (honesty + fold-in); V2's feel score was disqualified by a fabricated pre-checked stage — the honesty variant must not be the one surface that lies. Shipped = V1's ceremony with V2's elapsed counter, warming-card pattern and payoff line, plus V3's persistence and credit-at-call-end. The independently-run user test on the prior commit reached the same conclusion before the fold-in shipped ("the strongest first-run treatment in the product").
Documented deviation from the judge synthesis: the recommended right-column JourneyPanel (checks + n/5) was not folded in. It would recreate the exact two-progress-fractions contradiction the 2026-07-07 audit eliminated (the deploy block is the page's single fraction; the rail owns done-state) and violate the spec's own R10 (no second competing checklist). The endowed-progress insight lands in the ceremony's final beat instead; journey-progress flags exist for future rail styling if evidence demands it.

What shipped

The ceremony — provisioning-ceremony.tsx

  • 3 stages naming plausible work: create project → provision Aria → warm voice pipeline
  • “Usually under 40 seconds · ns in” — estimate + live counter, no invented %
  • Stall state: stage named, finished work stays done, retry re-runs ONLY that step, status.agora.io escape
  • Break-the-wall: after stage 1, “Continue to Studio” → landing renders with Aria warming (Talk disabled WITH its promise)
  • Arrival beat: “Aria is live — say hello” in a persistent polite live region
  • Once per browser (sx:provisioned); ?provision=1 replays, ?provision=stall demos the error

The landing additions (locked layout untouched)

  • Named default strip: “Runs Agora Balanced — smart model by default” + models rendered from STACK_PRESETS.balanced (can't drift) + “Change any part of it” → step 1
  • Trust line: “Provisioned free for you — talking in-browser costs nothing”
  • Checklist deleted; lib/journey-progress.ts keeps the flags; playground credits “hear” at call end
  • Template sheet: stack chips (llm · asr · tts) + Popular badge

The user-test fix train (same commit)

The X1 session (3 personas · 76.7% success · 2×S1 · 9×S2 · SUS 72) filed fixes that rode this commit: list-view import now lands in the playground (S1 — a success toast may never produce nothing); batch pre-flight (S2 — Deploy on an outbound agent confirms 248 contacts, caller ID, window, an honest ~$50 estimate, and offers “Talk to it first”); Pause/Resume in the agents row menu (S2 — Delete is no longer the only off-switch). Measurement

Watch: aria_conversation_started rate and time-to-first-reply (Believe), ceremony completion vs skip rate, agent_test_started/ended after arrival, and the journey flags' correlation with deployment_went_live. Counter-metric: ceremony abandon (close/bounce during the wait) — if the wait loses more users than the arrival converts, shorten stages before adding spectacle.
